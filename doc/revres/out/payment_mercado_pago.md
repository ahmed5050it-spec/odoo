# payment_mercado_pago — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` +
> behavioral code-reads + the `PROMPT.md` template.*

The **Payment Provider: Mercado Pago** module (`payment_mercado_pago`, category
*Accounting/Payment Providers*, `application=False`) is the **Mercado Pago
acquirer adapter** for Odoo's payment engine, covering several Latin-American
countries. It depends on exactly one module — **`payment`** — and exists only to
make Mercado Pago a usable, live payment provider: it teaches
`payment.provider`/`payment.transaction`/`payment.token` how to talk to Mercado
Pago over HTTP (OAuth-authenticated), how to tokenize cards in the browser with
the Mercado Pago JS SDK, and how to verify settlement on its return/webhook
callbacks. It owns **no models and no views** — three `_inherit` extensions graft
OAuth credentials, the Checkout-Pro/direct-payment flows, and a saved-card field
onto the engine. This is a textbook **metadata gap #7**: a real external
integration whose endpoints, OAuth-key auth, and trust model live in code, not in
field metadata.

## Role & Dependencies

| Depends on | Why |
|------------|-----|
| `payment` | The provider/transaction/token engine + the centralized outbound HTTP helper `payment.provider._send_api_request` and the guarded transaction state machine this module plugs Mercado Pago into. |

**Adds on top:** Mercado Pago OAuth credentials (access / refresh token + expiry,
public key, account country), the hosted **Checkout Pro** redirect flow, a
**direct in-browser card** charge via the Mercado Pago JS SDK, **tokenization**
(vaulted customer + card for off-session charges), per-country **currency
binding** across AR/BR/CL/CO/MX/PE/UY, the Mercado Pago **wallet** + local card
brands, and **OAuth self-onboarding** through Odoo's proxy with automatic token
refresh.

## Data Model (the ERM)

| Model (`_name`) | Kind | #fields | Key relations |
|-----------------|------|--------:|---------------|
| `payment.provider` | _inherit | +6 | `code` (+'mercado_pago'), `mercado_pago_account_country_id` (→`res.country`, drives currency), `mercado_pago_access_token` / `_refresh_token` / `_access_token_expiry` / `_public_key` (all group_system) |
| `payment.transaction` | _inherit | +0 | 11 methods overriding rendering/request/notification hooks; maps a tx ↔ a Mercado Pago preference / payment (`provider_reference` = payment id, `external_reference` = tx.reference) |
| `payment.token` | _inherit | +1 | `mercado_pago_customer_id`; `provider_ref` = Mercado Pago card id |

**No own model, no own views** — `xml_loc≈136` is view *inheritance* (account
country + *Connect* OAuth button + credential fields on the provider form), QWeb
inline-form + SDK-loader templates (incl. an `authorization_error` page), and
provider seed data. The cross-system keys (`provider_reference`,
`external_reference`, `provider_ref`, `mercado_pago_customer_id`) are the real
center of gravity — they bind Odoo records to Mercado Pago objects.

## Behavior & Surfaces

- **Routes:** 4. `/payment/mercado_pago/payments` (public **jsonrpc**, in-browser
  tokenized card charge), `/payment/mercado_pago/return` (public redirect-return),
  `/payment/mercado_pago/webhook/<reference>` (public, **csrf=False**, async
  notifications), `/payment/mercado_pago/oauth/return` (`auth=user`, CSRF-checked
  OAuth code return).
- **Views:** **1 form** (provider-form inheritance) — all UX is inheritance into
  the provider form + payment QWeb templates that mount the Mercado Pago JS SDK on
  pages with a payment form.
- **Frontend (static):** 1 JS file, **no OWL**, 0 registry adds — it **patches**
  `PaymentForm.prototype` to mount the Mercado Pago JS SDK and tokenize the card
  client-side; assets in `web.assets_frontend`.
- **Security:** **0 own ACL/record rules/groups** — leans on `payment`; all four
  OAuth credential fields are restricted to `base.group_system`.

What metadata cannot show, established by reading the code:

- **`_get_specific_rendering_values` / `_mercado_pago_prepare_preference_request_payload`**
  — the default redirect flow POSTs a **Checkout Pro preference** to
  **`https://api.mercadopago.com/checkout/preferences`** (items + payer + 
  `external_reference` + `notification_url`), then reads `init_point` (or
  `sandbox_init_point` when the provider is not `enabled`) and re-embeds its query
  params as hidden inputs so the buyer is bounced to the hosted page. Amounts are
  normalized by `_mercado_pago_convert_amount` (COP/HNL/NIO rounded **DOWN** to 0
  decimals, deviating from ISO 4217).
- **`_send_payment_request` / `/payment/mercado_pago/payments`** — the direct paths
  POST to **`/v1/payments`** with an **idempotency key**. The off-session token
  charge first POSTs `/v1/card_tokens` (from the saved `card_id`) to mint a fresh
  single-use token; the jsonrpc route takes the token the **Mercado Pago JS SDK**
  produced in the browser. Auth is `Authorization: Bearer <access_token>` +
  `X-Platform-Id` + `X-Idempotency-Key` (built in `_build_request_headers`).
- **`MercadoPagoPaymentController` return + webhook** — there is **no signed-webhook
  (HMAC) scheme**. Both `/return` and `/webhook/<reference>` funnel into
  **`_verify_and_process`**, which `_search_by_reference`s the tx and then **GETs
  `/v1/payments/<id>`** from `api.mercadopago.com` to fetch authoritative data
  before `_process('mercado_pago', …)`. The webhook filters out IPNs (acts only on
  `action` ∈ `payment.created`/`payment.updated`); the return skips `payment_id ==
  'null'` (buyer cancelled). **The trust boundary is the verification GET, not the
  inbound request.**
- **OAuth onboarding (proxy)** — `action_start_onboarding` gates on
  `SUPPORTED_COUNTRIES`, then redirects (`act_url`) to the authorize URL via Odoo's
  **proxy `https://mercadopago.api.odoo.com/api/mercado_pago`**; the
  `oauth/return` controller validates the **CSRF token** (`Forbidden` on failure),
  POSTs `/get_access_token` to exchange the code, writes the OAuth tokens + public
  key, and flips the provider to `state='enabled', is_published=True,
  allow_tokenization=True`. `_mercado_pago_fetch_access_token` transparently
  refreshes via `/refresh_access_token` (expiry backdated 31 days). `_apply_updates`
  maps Mercado Pago `status` through `const.TRANSACTION_STATUS_MAPPING` into
  `_set_pending/_set_done/_set_canceled/_set_error`.

## Value-Configuration Classification

**Value model: Network (mediating-technology acquirer integration).**
`payment_mercado_pago` interconnects two parties who would not otherwise transact
directly — the LatAm **cardholder/wallet holder** and the **merchant** — by
linking the merchant into Mercado Pago's payment network. It shows all three
mediating-technology activities: **network promotion & contract management** (OAuth
self-onboarding via the Odoo proxy, per-country eligibility + currency binding,
token/key management), **service provisioning** (creating the Checkout Pro
preference or direct `/v1/payments` charge and verifying settlement per
transaction), and **infrastructure operation** (the `api.mercadopago.com` server
link, the Mercado Pago JS SDK client channel, the verify-GET return/webhook loop).
It is **not** transformation (chain) or bespoke problem-solving (shop). It inherits
the parent `payment` engine's classification — the engine is the generic mediator,
this module its **Mercado Pago realization (gap #7)**. Classified **network /
support** (mirrors the sibling `payment_stripe.metamodel.json`; differs mainly in
the **trust model** — an authenticated verification GET rather than a signed
webhook — and in **OAuth-by-proxy** onboarding rather than Connect).

## How to Drive It

Use the `run-odoo` skill. With a `-i payment_mercado_pago` database and a Mercado
Pago provider connected (OAuth) in test state:

```python
# odoo shell — provider + feature flags + currency binding
p = env['payment.provider'].search([('code','=','mercado_pago')], limit=1)
print(p.name, p.state, p.mercado_pago_account_country_id.code, p.support_tokenization, p.allow_tokenization)
print(p.available_currency_ids.mapped('name'))  # enforced single currency per account country
# Mercado-Pago-specific override surface + a transaction <-> MP object link
print([m for m in dir(env['payment.transaction']) if m.startswith('_mercado_pago_')])
tx = env['payment.transaction'].search([('provider_code','=','mercado_pago')], limit=1)
print(tx.reference, tx.state, tx.provider_reference)  # provider_reference == MP payment id
```

```bash
# webhook has no HMAC: a spoofed id simply fails to resolve to a real payment
curl -X POST https://<host>/payment/mercado_pago/webhook/<bad-ref> \
  -H 'Content-Type: application/json' -d '{"action":"payment.created","data":{"id":"0"}}'
# non-enabled providers use sandbox_init_point; pay with a Mercado Pago sandbox test buyer/card
```
