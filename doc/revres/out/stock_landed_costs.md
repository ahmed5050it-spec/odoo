# stock_landed_costs — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` +
> behavioral code-reads, narrated per the `PROMPT.md` template.*

The **WMS Landed Costs** module (`stock_landed_costs`, category *Supply
Chain/Inventory*, `application=False`, v1.1) lets a business fold *extra costs* —
freight, customs duties, insurance, handling — into the **book value** of
received goods. It is a thin but pivotal bridge between logistics and the ledger:
only **3 own models** and ~3.2k Python LOC, yet it reaches into the inventory
valuation layer and the general ledger at once. It depends on `stock_account`
(inventory valuation) and `purchase_stock` (receipts from purchase orders). Its
center of gravity is `stock.landed.cost` → its `cost_lines` (what to charge and
how to split) and its computed `valuation_adjustment_lines` (per-move cost
allocation), validated into a posted `account.move` and a re-costed `stock.move`.

## Role & Dependencies

| Depends on | Why (inferred) |
|------------|----------------|
| `stock_account` | Inventory valuation layer it adjusts (`stock.move._set_value`, valuation accounts). |
| `purchase_stock` | Receipts originate from purchase orders; vendor bills carry the freight/duty lines. |

**Adds on top:** a landed-cost document, a five-way cost-distribution engine, the
vendor-bill → landed-cost shortcut, and the automatic posting of a
debit-stock-valuation / credit-expense revaluation journal entry.

## Data Model (the ERM)

| Model (`_name`) | Description | #fields | Key relations |
|-----------------|-------------|--------:|---------------|
| **`stock.landed.cost`** | Stock Landed Cost (the document) | 14 | `picking_ids→stock.picking`, `cost_lines→stock.landed.cost.lines`, `valuation_adjustment_lines→stock.valuation.adjustment.lines`, `account_move_id`/`vendor_bill_id→account.move`, `account_journal_id→account.journal` |

| **`stock.valuation.adjustment.lines`** | Per-move computed cost allocation | 12 | `cost_id→stock.landed.cost`, `cost_line_id→stock.landed.cost.lines`, `move_id→stock.move`, `product_id→product.product` |

**Central model:** `stock.landed.cost`. The module also **inherits** seven existing
models (no new `_name`): `account.move` (smart button + `landed_costs_ids`),
`account.move.line` (`is_landed_costs_line`), `product.template`
(`landed_cost_ok`, `split_method_landed_cost`), `purchase.order.line`,
`stock.move` (`_get_value_from_extra`), and `res.company` / `res.config.settings`
(`lc_journal_id`). Field profile is amount-centric: 5 `Monetary`, 16 `Many2one`,
5 `Selection` (mostly the split-method enum and state).

## Behavior & Surfaces

- **Routes:** 0 — no HTTP/JSON-RPC surface; entirely backend ORM + UI.
- **Views:** form (3), list (4), kanban (1), search (1). Plus a *Create Landed
  Costs* smart button injected on the `account.move` (vendor bill) form.
- **Security:** 3 access rules, **1 record rule** (multi-company on
  `stock.landed.cost`), **0 own groups** — all three models are gated on the
  borrowed `stock.group_stock_manager`.
- **Frontend:** none — 0 JS/OWL files, 0 registry adds, no asset bundles
  (static). The UI is pure server-rendered XML.

The metadata cannot show what *validating a landed cost* does. Code reads establish:

- **`button_validate`** — the spine. Auto-runs `compute_landed_cost` if needed,
  guards `_check_sum`, then for each adjustment line on a `real_time`-valuated
  product builds an `account.move` (`move_type='entry'`), creates + `_post()`s it,
  flips `state` draft→done, and calls `valuation_adjustment_lines.move_id._set_value()`
  to push the cost into the stock valuation layer. Irreversible (cancel raises;
  reverse with a negative cost).
- **`compute_landed_cost`** — the split algorithm: allocates each cost line's
  `price_unit` across the receipt's moves by `split_method` — `equal`,
  `by_quantity`, `by_weight`, `by_volume`, `by_current_cost_price` — HALF-UP
  rounded, with the residual rounding-diff added to the largest line so totals
  reconcile exactly.
- **`get_valuation_lines` / `_get_targeted_move_ids`** — the link to the
  **receipt**: targets `picking_ids.move_ids`, but only **FIFO/average**,
  real-cost products (standard-cost products raise a `UserError`); seeds
  `former_cost = move._get_value()` and weight/volume per received qty.
- **`account.move.button_create_landed_costs` / `landed_costs_ids`** — the link
  to the **vendor bill**: a freight/duty bill whose lines are flagged
  `is_landed_costs_line` (driven by `product.template.landed_cost_ok`) spawns a
  landed cost copying those lines into `cost_lines`; `vendor_bill_id` closes the
  loop.
- **`_create_account_move_line` / `stock.move._get_value_from_extra`** — posts
  **debit stock valuation / credit expense**, scaled by `remaining_qty/quantity`
  (only stock still on hand is capitalised; consumed qty hits COGS), reversing
  for negative costs; the inventory side adds `additional_landed_cost` back into
  the move's value with a readable per-cost breakdown.

## Value-Configuration Classification

**Value model: Support (Porter support activity / cost accounting).** Unlike
`stock` (a primary value-chain *chain* activity that physically moves goods),
`stock_landed_costs` moves no goods — it corrects their **book value**. It
capitalises extra costs into inventory and writes the matching ledger entry,
which is firm-infrastructure cost accounting. Classified **support / support**:
it is the cost-accounting complement to the receipt, feeding the financial
ledger rather than the goods flow.

## APQC PCF Hint

**9.0 Manage Financial Resources.** It belongs to the general accounting /
inventory-valuation side of 9.x: it adjusts product cost and posts a stock
revaluation `account.move`, the cost-accounting bridge between the
`stock_account` valuation layer and the GL. It is adjacent to the receipt
(APQC 4.0 *Deliver Physical Products*, where `stock` sits) but is itself a
financial-management support process, not a logistics step. Per
`apqc_odoo_map.tsv`, this aligns with the same 9.x family that `account` covers
for AR/AP (9.2/9.5).

## How to Drive It

Use the `run-odoo` skill (`.claude/skills/run-odoo/`). With the server up and a
database having `stock_landed_costs` installed:

```python
# odoo shell
done = env['stock.landed.cost'].search([('state','=','done')], limit=5)
print(done.mapped(('name','amount_total','account_move_id.name')))
# compute then validate a draft landed cost:
lc = env['stock.landed.cost'].search([('state','=','draft')], limit=1)
lc.compute_landed_cost()
print(lc.valuation_adjustment_lines.mapped(('product_id.display_name','former_cost','additional_landed_cost','final_cost')))
lc.button_validate(); print(lc.state, lc.account_move_id.name)  # posted debit-stock-valuation / credit-expense
# vendor-bill -> landed cost:
bill = env['account.move'].search([('move_type','=','in_invoice'),('landed_costs_visible','=',True)], limit=1)
bill.button_create_landed_costs()
```
