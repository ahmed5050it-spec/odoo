# transifex — Reverse-Engineering Brief

> *Generated by the revres workflow (AGENT_WORKFLOW.md): facts from
> `extract_module.py` + `extract_frontend.py`, behaviour from code-read, narrative
> per `PROMPT.md`. DEEP upgrade of the BASELINE record.*

The **Transifex integration** module (`transifex`, category *Hidden/Tools*,
`application=False`) does one focused thing: it adds a *"translate on Transifex"*
deep link next to each translatable term so translators jump straight from an
Odoo field into the exact string/language/project in the Transifex web editor.
It is **not** auto-installed, depends only on `base` and `web`, is ~252 Python
LOC, and owns **no business object of its own** — its two real models are a URL
builder and a materialized translation-term cache.

## Role & Dependencies

| Depends on | Why |
|------------|-----|
| `base` | Overrides `base.get_field_translations`; reads `res.lang`, `ir.config_parameter`, `ir.module.module`; ships an `ir.cron`. |
| `web` | Extends the web `TranslationDialog` (QWeb `t-inherit`) and registers a list-view controller. |

**Adds on top:** a per-term Transifex deep link in the translation dialog, a
module→Transifex-project map from `.tx/config`, a browsable code-translation
list with a Reload button, and a 7-day refresh cron.

## Data Model (the ERM)

| Model (`_name`) | Description | #fields | Notes |
|-----------------|-------------|--------:|-------|
| **`transifex.code.translation`** | Code Translation | 5 | Flat denormalized term table (`source`, `value`, `module`, `lang`, computed `transifex_url`); `_log_access=False`. No FK relations. |
| **`transifex.translation`** | Transifex Translation | 0 | `AbstractModel`; the URL-builder service (`_get_transifex_projects`, `_update_transifex_url`). |
| `base` *(extension)* | — | — | `_inherit='base'`: wraps `get_field_translations` to stamp each term with its module + `transifex_url`. |

No `Many2one` relations — links to `res.lang` / `ir.module.module` are by code
and name, not foreign keys. Center of gravity is the `transifex.translation`
**service**, not stored data.

## Behavior & Surfaces (code-read)

- **URL synthesis** (`_update_transifex_url`): assembles
  `base_url/project/translate/#<lang_iso>/<module>/42?q=text%3A<source>` from four
  slugs — config base URL, `.tx/config` project, `res.lang.iso_code` (skips
  `en_US`), module name. Source truncated to 50 chars, encoded; resource id `42`
  is an arbitrary placeholder to satisfy Transifex's URL shape. **No network I/O.**
- **Project discovery** (`_get_transifex_projects`): `@ormcache`d walk of
  `addons.__path__` parsing `.tx/config` (legacy `odoo-16.base` and colon
  `o:odoo:p:odoo-16:r:base` formats). Modules absent from any `.tx/config` get no
  link — by design only mainline Odoo modules are linkable.
- **base override** (`models/models.py`): after `super().get_field_translations`,
  resolves the record's external id → owning module (must be in `_init_modules`),
  stamps `module`, calls `_update_transifex_url`. This feeds the dialog with no
  new route.
- **Code-translation materialization** (`_load_code_translations` / `reload`):
  `.po` code terms aren't in `ir.translation`, so rows are bulk-created under an
  `EXCLUSIVE NOWAIT` table lock; the 7-day `ir.cron` *"Transifex: Reload code
  translations"* runs `reload()` = `DELETE` then reload.

## Frontend (gap #3) & Integrations (gap #7)

- **Frontend:** 1 JS, 2 XML, `web.assets_backend` (3 entries), **no OWL class**.
  `translation_dialog.xml` `t-inherit`s `web.TranslationDialog` and injects an
  `<a target="_blank">` **fa-globe "Contribute"** link bound to
  `term.transifex_url` — the actual deep-link widget.
  `reload_code_translations_views.js` subclasses `ListController`, registers view
  `transifex_code_translation_tree` with a **Reload** button calling `reload()`.
- **Integrations:** `http_call_sites=0`, no SDK, no API keys. The only endpoint is
  the link target `https://www.transifex.com/odoo/` (data file seeds
  `https://app.transifex.com/odoo` into `transifex.project_url`). The module
  **deep-links only**; the user's browser does the navigation.

## How to Drive It

Use the `run-odoo` skill with the module installed:

```python
# odoo shell
env['ir.config_parameter'].sudo().get_param('transifex.project_url')   # base URL
env['transifex.translation']._get_transifex_projects()                 # module -> tx project
t=[{'source':'Sale Order','module':'sale','lang':'fr_FR'}]
env['transifex.translation']._update_transifex_url(t); print(t)        # built deep link
env['transifex.code.translation'].reload()                             # repopulate cache
# UI: open any translatable field's Translation dialog -> click the globe icon.
```
