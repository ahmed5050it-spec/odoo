# iot_drivers — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` +
> behavioral code-reads + the `PROMPT.md` template.*

The **Hardware Proxy** module (`iot_drivers`, category *Hidden*,
`application=False`, `installable=False`) is the **firmware runtime** for the
Odoo IoT Box — a Raspberry Pi or Windows embedded device that bridges physical
hardware peripherals (receipt printers, barcode scanners, payment terminals,
scales, displays, keyboards) to the Odoo backend via WebSocket and HTTP. With
5,873 Python LOC and zero ORM models, it is not a standard Odoo addon in the
usual sense: it runs *on* the IoT Box OS, not inside a multi-tenant Odoo
instance, and has no business logic, no database models, and no user-facing
Odoo UI. Its entire purpose is hardware abstraction, device lifecycle management,
and real-time bidirectional communication with the Odoo server.

## Role & Dependencies

No Odoo module dependencies (empty `depends: []`). It imports `odoo.http`,
`odoo.service`, and `odoo.tools` directly but runs as a standalone daemon on
the IoT Box, not as part of an installed Odoo database module. Concrete device
driver modules (e.g. `iot_scale`, `iot_printer`) are expected to extend its
`Driver` and `Interface` base classes.

## Architecture — the four runtime objects

| Object | Role |
|--------|------|
| `Manager` (Thread, `main.py`) | Boot orchestrator: starts nginx, checks TLS cert, registers with Odoo, polls device changes every 3 s |
| `Interface` (Thread, `interface.py`) | Per-connection-type scanner: polls `get_devices()` every `_loop_delay` s, diffs against known devices, starts/stops Driver threads |
| `Driver` (Thread, `driver.py`) | Per-device worker: holds `_actions` dict, dispatches action commands, writes `data` dict for event reporting |
| `EventManager` (`event_manager.py`) | Fanout: on `device_changed()` fires to WebSocket controller, WebRTC client, and long-polling sessions |

Global state lives in four module-level dicts in `main.py`:
`drivers`, `interfaces`, `iot_devices`, `unsupported_devices`.

## Behavior (code-read)

### Boot sequence (`Manager.run`, `main.py`)

1. Remount filesystems rw (RPi only), reconnect Wi-Fi.
2. Start nginx (`helpers.start_nginx_server()`).
3. Call `certificate.ensure_validity()` — checks TLS cert expiry; downloads a
   new x509 from `https://www.odoo.com/odoo-enterprise/iot/x509` if needed.
4. POST `{iot_box: {...}, devices: {}}` to `/iot/setup` on the configured Odoo
   server; receive WebSocket channel name in response.
5. `helpers.download_iot_handlers()` / `helpers.load_iot_handlers()` — fetch
   and import driver code from the Odoo server.
6. Start all registered `Interface` threads.
7. Start `WebsocketClient` thread on the received channel.
8. Loop every 3 s: if `_get_changes_to_send()` detects device-list, IP, or
   version changes, re-POST to `/iot/setup`.
9. Daily at 00:00: renew cert, reset log level, check git branch.

### WebSocket message dispatch (`WebsocketClient.on_message`, `websocket_client.py`)

Subscribes to the Odoo Bus channel returned by `/iot/setup`. Dispatches by
`message['message']['type']`:

| Message type | Behavior |
|---|---|
| `iot_action` | Calls `iot_devices[device_id].action(payload)` on the matching Driver |
| `server_clear` | Calls `helpers.disconnect_from_server()` |
| `server_update` | Updates `remote_server` in conf |
| `restart_odoo` | Calls `helpers.odoo_restart()` |
| `webrtc_offer` | Forwards to `webrtc_client.offer()`, returns WebRTC answer |
| `remote_debug` | Toggles ngrok tunnel via `helpers.toggle_remote_connection()` |
| `test_connection` | Calls `helpers.check_network()` for LAN + WAN quality |
| `bundle_changed` | Triggers `upgrade.check_git_branch()` (detects DB upgrade) |

All action results are reported back via POST to `/iot/box/send_websocket`.

### Cloud pairing (`ConnectionManager`, `connection_manager.py`)

When the IoT Box has no configured Odoo server URL, `ConnectionManager` polls
`https://iot-proxy.odoo.com/odoo-enterprise/iot/connect-box` with exponential
backoff (15 s → ~40 s, max ~329 requests over 2 h) to:
1. Register the box and receive a `pairing_code` + `pairing_uuid`.
2. On RPi, attempt to print the pairing code on any connected USB
   receipt/label printer.
3. Poll until the user enters the pairing code in Odoo; on success the proxy
   returns `{url, token, db_uuid, enterprise_code}`.
4. Save credentials, call `manager._send_all_devices()`, switch git branch,
   restart Odoo.

### Driver/Interface plugin registration

`Driver.__init_subclass__` auto-appends every subclass to the global `drivers`
list. `Interface.__init_subclass__` registers every subclass by name into
`interfaces`. On boot, `Manager.run` calls `interface().start()` for each
registered Interface. Each Interface polls `get_devices()`, calls
`update_iot_devices()`, and calls `add_device(identifier, device)` for newly
detected hardware. `add_device` iterates `drivers` sorted by descending
`priority`, calls `driver.supported(device)`, and starts the first matching
Driver thread.

### Receipt printing (`PrinterDriverBase`, `iot_handlers/drivers/printer_driver_base.py`)

`PrinterDriverBase._actions` maps:
- `print_receipt` → decode base64 PNG → PIL convert to 1-bit B&W →
  `format_escpos()` or `format_star()` → `print_raw()`
- `cashbox` → send ESC/POS drawer-kick bytes (`\x1b\x3d\x01` etc.)
- `status` → print test page

`format_escpos()` parses the **printer name** for `__IMC_...__` option
strings to select raster (`GS v 0`) vs. column bit image (`ESC *`) mode with
optional scale factor. Duplicate actions suppressed via `LRU(256)` on
`action_unique_id`.

### SSL certificate management (`tools/certificate.py`)

Daily `ensure_validity()`:
1. Reads `/etc/ssl/certs/nginx-cert.crt`, checks common_name and expiry >
   now+10 days.
2. If invalid: POST `{db_uuid, enterprise_code}` to
   `https://www.odoo.com/odoo-enterprise/iot/x509` (up to 5 retries).
3. Writes `nginx-cert.crt` and `nginx-cert.key` to disk, restarts nginx.
4. Informs the Odoo DB via POST to `/iot/box/update_certificate_status`.

## Routes & Frontend

| Route | Auth | Notes |
|-------|------|-------|
| `/hw_proxy/hello` | none | Ping / health check |
| `/hw_proxy/status_json` | none | Returns `{driver: status}` for proxy drivers |
| `/hw_proxy/scale_read` | none | Serial scale weight (JSON-RPC) |

**Frontend:** 20 JS files, 0 XML templates, 16 OWL components in asset bundle
`iot_drivers.assets`. This is a **standalone OWL SPA** served from the IoT Box
local HTTPS homepage — not loaded in the Odoo backend. Components provide the
local admin UI: device list (`DeviceDialog`), Wi-Fi config (`WifiDialog`),
server pairing (`ServerDialog`), firmware update (`UpdateDialog`), remote debug
(`RemoteDebugDialog`), SIX payment terminal config (`SixDialog`), time setting
(`TimeDialog`).

## Fit-to-Standard

| Capability | Standard fit |
|------------|-------------|
| ESC/POS receipt printing | Standard — raster and column modes, drawer kick |
| Cloud pairing via iot-proxy.odoo.com | Standard — QR code scan in Odoo backend |
| USB / serial / network device discovery | Standard via Interface plugin framework |
| Custom proprietary hardware | Gap — requires a new Driver + Interface subclass |
| WebRTC display mirroring | Gap — wired in but production coverage unclear |
| Windows IoT | Partial — IS_WINDOWS guards present but secondary path |
