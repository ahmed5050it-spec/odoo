# hr_holidays — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` +
> `extract_frontend.py` + targeted code-read of the key models.*

The **Time Off** module (`hr_holidays`, category *Human Resources/Time Off*,
`application=True`) manages employee **leave requests** and **allocations**. It
depends on `hr` (employee/department master data), `calendar` (meeting events)
and `resource` (working-time calendars). Its center of gravity is `hr.leave`
(~51 fields, 79 methods) — the request document — paired with
`hr.leave.allocation` (the balance) and `hr.leave.type` (the policy). The module
is **not** auto-installed and exposes 5 backend HTTP approval routes.

## Role & Dependencies

| Depends on | Why (inferred) |
|------------|----------------|
| `hr` | Employee, department, manager (`leave_manager_id`) the leave belongs to. |
| `calendar` | Optional confidential `calendar.event` mirroring an approved leave. |
| `resource` | `resource.calendar` working hours + `resource.calendar.leaves` blocking. |

**Adds on top:** the leave request approval workflow, leave-type policies
(units, paid/unpaid, validation mode), allocations with multi-level accrual
plans + carryover, mandatory days / public holidays, and a time-off dashboard.

## Behavior & Surfaces

Code-read findings metadata cannot show:

- **Approval state machine.** Created `confirm` (To Approve); `action_approve`
  writes `validate1` (Second Approval, sets `first_approver_id`) when
  `validation_type=='both'`, else `_action_validate` writes `validate` (sets
  approver ids). `action_refuse` writes `refuse`, archives the meeting and posts
  chatter. Transitions/approver bookkeeping are pure Python.
- **Calendar blocking.** Final validation runs `_validate_leave_request →
  _create_resource_leave`, sudo-creating a `resource.calendar.leaves`
  (`holiday_id→hr.leave`) that removes the period from working hours so
  attendance/payroll/planning see the person as unavailable; cancel/refuse calls
  `_remove_resource_leave`.
- **Allocation gate.** `_check_validity` calls `hr.leave.type.get_allocation_data`
  and raises `ValidationError` when `max_leaves==0` or `virtual_remaining_leaves`
  would breach `allows_negative`/`max_allowed_negative`; also blocks mandatory
  days for non-officers.
- **Accrual + remaining-days.** `leaves_taken`/`max_leaves`/
  `virtual_remaining_leaves` are computed (not stored) via
  `_get_consumed_leaves`. Cron `_update_accrual` → `_process_accrual_plans` walks
  accrual levels from `lastcall`/`nextcall`, increments `number_of_days` by
  `added_value`, applies caps, carryover and level transitions.
- **Double validation.** `_check_double_validation_rules` /
  `_check_approval_update` require a first approver (officer) then a second/HR
  approver before resource leaves are created (`can_approve`/`can_validate`).
- **Public-holiday reevaluation.** A global `resource.calendar.leaves`
  create/write/unlink triggers `_reevaluate_leaves`, which recomputes overlapping
  `hr.leave`, grants/takes days, and can auto-refuse leaves that no longer fit.
