# sale_pdf_quote_builder — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` +
> `extract_frontend.py`, deepened with code-read behavioral notes per
> `PROMPT.md`.*

**Sales PDF Quotation Builder** (`sale_pdf_quote_builder`, category *Sales/Sales*,
`application=False`, `auto_install=True`) composes rich PDF quotations by
assembling reusable PDF document blocks — headers, footers and per-product
documents — onto a `sale.order` and filling their PDF AcroForm fields from live
order data at render time. It auto-installs on top of `sale_management`, so it
silently enriches the existing quotation document of the Quote-to-Cash chain
rather than introducing a new flow. Its center of gravity is the
`quotation.document` block (a delegated `ir.attachment`) plus the
`sale.pdf.form.field` mapping that drives PDF form-field substitution, both
consumed by an override of `ir.actions.report._render_qweb_pdf_prepare_streams`
that merges everything with `pypdf`.

## Role & Dependencies

| Depends on | Why (inferred) |
|------------|----------------|
| `sale_management` | Pulls in `sale` (the order engine it extends: `sale.order`, `sale.order.line`, `sale.order.template`) and the quotation-template layer onto which header/footer blocks attach. |

**Adds on top:** reusable header/footer PDF blocks, product PDFs merged *inside*
the quote, automatic AcroForm-field discovery with dynamic (path-driven) and
customizable (free-text) mapping, an in-form OWL configurator to pick blocks and
type field values, and a render-time `pypdf` assembly + form-fill step.

## Data Model (the ERM)

| Model (`_name`) | Description | #fields | Key relations |
|-----------------|-------------|--------:|---------------|
| **`quotation.document`** | Quotation's Headers & Footers | 7 | `ir_attachment_id→ir.attachment` (`_inherits`), `quotation_template_ids→sale.order.template` (`header_footer_quotation_template_rel`), `form_field_ids→sale.pdf.form.field` |
| **`sale.pdf.form.field`** | PDF form-field mapping | 5 | `product_document_ids→product.document`, `quotation_document_ids→quotation.document` |
| `ir.actions.report` *(ext)* | overrides PDF stream prep | 0 | merges/fills the final PDF |
| `product.document` *(ext)* | adds `attached_on_sale='inside'` | +2 | `form_field_ids→sale.pdf.form.field` |
| `sale.order` *(ext)* | selected docs + custom values | +4 | `quotation_document_ids→quotation.document`, `customizable_pdf_form_fields` (JSON) |
| `sale.order.line` *(ext)* | per-line product PDFs | +2 | `product_document_ids→product.document` |
| `sale.order.template` *(ext)* | template header/footer set | +1 | `quotation_document_ids→quotation.document` |

**Central model:** `quotation.document` — a reusable PDF block that delegates
storage to `ir.attachment` (`_inherits`, a mixin-style delegation) and is shared
with `sale.order.template` through the symmetric `header_footer_quotation_template_rel`
relation. The five `_inherit`-only models are extensions, not new entities. The
field set is **relational-heavy** (`Many2many` dominates: 10), reflecting that
the module is mostly about wiring documents, form fields, templates and orders
together rather than carrying its own attributes.

## Behavior & Surfaces

- **Routes:** 1 — `/sale_pdf_quote_builder/quotation_document/upload`
  (`auth='user'`, `type='http'`): the backend upload surface for header/footer
  PDFs. No public/portal endpoint; everything else is ORM-driven.
- **Views:** form (1), list (2), **kanban (1)**, search (2) — a small backend
  surface for managing documents and form fields, with the kanban driving the
  custom quotation-document view.
- **Security:** 4 access rules, **1 record rule** (multi-company scoping on
  `quotation.document`), 0 new groups — it reuses `sales_team` and `base`
  groups (manager writes documents, system writes form fields, users read).
- **Frontend (gap #3):** 5 JS files, 3 XML templates, **2 OWL components**
  (`CustomContentKanbanLikeWidget`, `CustomFieldCard`) — an in-form configurator
  that calls `get_update_included_pdf_params`, toggles included blocks and writes
  `quotation_document_ids` + `customizable_pdf_form_fields`; backend-only bundle.
- **Integrations (gap #7):** none — no HTTP/SDK/api-key usage.

## Value-Configuration Classification

**Primary model: Value Chain (transform), sales-document enrichment.**
`sale_pdf_quote_builder` does not create a new downstream document; it enriches
the existing `sale.order` quotation — the primary deliverable of the
Quote-to-Cash chain — with assembled header/footer/product PDF blocks merged via
`pypdf` and AcroForm fields filled from live order values. Operating at
quotation-render time on the *Market & Sell* primary activity, its value-creation
is the linear, document-producing transformation characteristic of a **chain**
(not shop/network/support). Activity class: **primary**.

## How to Drive It

Use the `run-odoo` skill (`.claude/skills/run-odoo/`). With the server up and an
`-i sale_pdf_quote_builder` database:

```python
# odoo shell
env['quotation.document'].search([]).mapped(('name', 'document_type', 'add_by_default'))
env['sale.pdf.form.field'].search([]).mapped(('name', 'document_type', 'path'))
# trigger the merge/assembly on an order that has selected documents:
so = env['sale.order'].search([('quotation_document_ids', '!=', False)], limit=1)
env['ir.actions.report']._render_qweb_pdf_prepare_streams(
    'sale.report_saleorder', {}, res_ids=so.ids)
# inspect what the OWL configurator is offered:
so.get_update_included_pdf_params()
# backend upload route (auth=user, http): /sale_pdf_quote_builder/quotation_document/upload
```

## Open Questions (verify in code)

  template-supplied header carry `add_by_default` for the same order.
- How dynamic path values are localized when the order partner timezone differs
  from the rendering user (tz fallback chain partner → user → UTC).
- Behaviour difference between a blank customizable field and a dynamic path
  resolving to empty (both yield `''` but differ in source/auditability).
- Whether non-text AcroForm widgets (checkbox/radio/signature) are silently
  dropped by the read-only text-fill path.
