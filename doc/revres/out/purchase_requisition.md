# purchase_requisition — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` + code-read
> behavioral notes + the `PROMPT.md` template.*

The **Purchase Agreements** module (`purchase_requisition`, category *Supply
Chain/Purchase*, `application=False`) adds **strategic sourcing** on top of
`purchase`: long-term **blanket orders**, reusable **purchase templates**, and
**call-for-tenders** (competing RFQs compared to award the best vendor). It is a
thin extension — 5 own models, **0 routes**, ~1730 py / ~702 xml LOC, depending
only on `purchase`. Its center of gravity is `purchase.requisition` /
`purchase.requisition.line` (16 / 9 fields): the *agreement* document whose
confirmed lines publish vendor prices (`product.supplierinfo`) that downstream
purchase orders draw on. Where `purchase` runs the RFQ→PO→bill transaction, this
module is its **upstream procurement-support** layer.

## Role & Dependencies

| Depends on | Why (inferred) |
|------------|----------------|
| `purchase` | Extends `purchase.order` / `purchase.order.line` / `product.supplierinfo`; agreements feed and generate purchase orders. The *only* hard dependency. |

**Adds on top:** blanket-order & purchase-template agreements, vendor price
publication into `product.supplierinfo`, agreement→PO seeding, and a

## Key Behavior Beyond Metadata (code-read)

- **Agreement state machine** (`action_confirm` → `action_done`/`action_cancel`):
  `draft → confirmed → done (Closed) / cancel`. Confirm rejects an empty
  agreement; for a **blanket order** it requires every line `price>0` & `qty>0`,
  then publishes supplierinfo. **Close** is blocked while any linked PO is still
  draft/sent/`to approve`, then unlinks the published prices.
- **`requisition_type`** = `blanket_order` (negotiated price+qty, feeds
  supplierinfo, tracks `qty_ordered`) vs `purchase_template` (reusable list, no
  commitment). Drives the `ir.sequence`; type/company is locked once non-draft.
- **`line._create_supplier_info`** — confirmed blanket lines mint a
  `product.supplierinfo` (vendor, product, negotiated price, currency,
  back-linked). Price edits propagate to it; `product._prepare_sellers` then
  **scopes** a requisition-linked PO to that agreement's prices — how an
  agreement becomes the price applied on generated POs.
- **`purchase.order._onchange_requisition_id`** — picking an agreement on a draft
  PO copies vendor/currency/company/terms and **seeds order lines** from the
  agreement (qty = template qty, or 0 for blanket draw-down).
- **Call for tenders** (`purchase.order.group` + `alternative_po_ids`) —
  `action_create_alternative` spawns competing RFQs to other vendors into a shared
  group; `get_tender_best_lines` picks best price / unit / earliest date per
  product; `button_confirm` pops `alternative.warning` to keep or cancel rivals.

## Value-Configuration Classification

**Value model: Support activity.** `purchase_requisition` is a **procurement
support** extension (strategic sourcing) in Stabell & Fjeldstad terms — it
provisions *inputs* upstream of the chain by negotiating blanket price
agreements and running tenders, so the primary activities (`stock`, `mrp`,
`sale`) get the right goods at the right price. It is not a primary transform: it
depends only on `purchase` and produces agreements/sourcing decisions, not a
delivered customer product. `activity_class = support`.

## How to Drive It

Use the `run-odoo` skill (`.claude/skills/run-odoo/`). With the server up and a
DB with `-i purchase_requisition`:

```python
# blanket order publishes a vendor price
req = env['purchase.requisition'].create({'requisition_type':'blanket_order',
    'vendor_id': p.id, 'line_ids':[(0,0,{'product_id':prod.id,'product_qty':10,'price_unit':5})]})
req.action_confirm(); print(req.state, req.line_ids.supplier_info_ids.mapped('price'))
# generate a PO from the agreement
po = env['purchase.order'].new({'requisition_id': req.id}); po._onchange_requisition_id()
print(po.order_line.mapped(('product_id.display_name','price_unit')))
# tender: create alternatives, compare best lines
po.action_create_alternative(); print(po.get_tender_best_lines())
```
