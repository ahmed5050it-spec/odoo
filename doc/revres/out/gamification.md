# gamification — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` +
> `extract_frontend.py` + targeted code-read of challenge/goal/badge/karma models.*

The **Gamification** module (`gamification`, category *Human Resources*,
`application=False`) is Odoo's engagement engine: it lets the business define
**goals** (KPI rules over any model), bundle them into recurring **challenges**
assigned to an audience, and reward achievement with **badges** and a **karma**
points-and-rank ladder. It is thin by dependency — it only depends on `mail`
(chatter, notifications, templated reports, `discuss.channel`) — but rich in
behavior: it reads other modules' data to score progress and emits badge/karma
side-effects. It ships **no** OWL/JS and **no** HTTP routes; the leaderboard UI
lives in consumer modules.

## Role & Dependencies

| Depends on | Why (inferred) |
|------------|----------------|
| `mail` | Chatter on challenges/badges, badge/rank/report mail templates, `discuss.channel` report copies, activity reminders. |

**Consumed by (real dependers):** `hr_gamification`, `gamification_sale_crm`,
`survey`, `website_profile` (and through karma, `website_forum` /
`website_slides`). gamification is itself a **support service**: it defines the
goal/badge/karma machinery that those apps wire to their own KPIs and points.

## Behavior & Surfaces

Code-read findings metadata cannot show:

- **Daily challenge cron.** `ir_cron_check_challenge` runs `_cron_update`: it
  starts draft challenges (`start_date<=today`), closes overdue ones, then
  `_update_all` joins `gamification_goal` to `mail_presence` in raw SQL so only
  goals of recently-active users are refreshed, recomputes the `user_domain`
  participant set, generates missing goals, and posts periodic reports.
- **Goal computation reads other models live.** `update_goal` scores `current`
  by querying `definition.model_id`: `count` → `search_count(domain)`, `sum` →
  `_read_group(domain, [], ['<field>:sum'])`. The stored `domain` (Char) is
  `safe_eval`'d with the goal's `user` injected and `start/end_date` appended on
  `field_date_id`. `python` mode `safe_eval`'s `compute_code` for a numeric
  `result`; `manually` mode only sends reminders.
- **Badge awarding chain.** `_check_challenge_reward` `_read_group`s reached
  goals per user; when all lines are reached it calls `_reward_user` →
  `gamification.badge.user.create(...)._send_badge()`. `create()` enforces
  `check_granting` / `_can_grant_badge` (`rule_auth` everyone/users/having/nobody
  + monthly `rule_max`), and `_send_badge` posts a "You've earned the X badge"
  notification. Top-3 prizes come from `_get_topN_users`.
- **Karma ledger & ranks.** gamification extends `res.users` with `karma`,
  `rank_id` and badge-level counts. Writing `karma` routes through
  `_add_karma_batch`, which appends a `gamification.karma.tracking` row;
  `_compute_karma` re-reads the latest tracking (DISTINCT ON SQL) and
  `_recompute_rank` assigns a `gamification.karma.rank` by `karma_min`, emailing
  on rank change. A monthly cron (`_consolidate_cron`) collapses old trackings.

**Frontend (gap #3):** none shipped — 0 JS files, 0 OWL components, 0 registry
adds/patches; only one `web.assets_backend` reference. UI is plain backend
form/list/kanban (6 form, 8 list, 4 kanban, 6 search). Rich leaderboards live in
consumers (e.g. `website_profile`).
**Integrations (gap #7):** no outbound HTTP/SDK, no API keys, no endpoints.

## Value-Configuration Classification

- **Value model:** `support` (Stabell & Fjeldstad). gamification is an HR
  engagement/motivation tool — a value-support configuration, not a primary
  chain/shop/network. It produces no product or order; it scores other modules'
  data and emits badges/karma to motivate the workforce.
- **Activity class:** `support`.
- Consumed as a support service by hr, survey, sale/crm and the website
  engagement stack rather than converting demand into delivered product.

## How to Drive It

```python
# challenges and their state/period
env['gamification.challenge'].search([], limit=5).mapped(('name','state','period'))
# reached goals with live-computed values
env['gamification.goal'].search([('state','=','reached')], limit=5).mapped(('definition_id.name','current','completeness'))
# badge grant counts
env['gamification.badge.user'].read_group([], ['badge_id'], ['badge_id'])
# karma leaderboard
env['res.users'].search([('karma','>',0)], limit=5).mapped(('login','karma','rank_id.name'))
```
