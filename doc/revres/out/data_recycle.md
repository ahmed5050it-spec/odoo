# data_recycle — Reverse-Engineering Brief

> *Generated by the revres workflow (AGENT_WORKFLOW.md): explorer evidence from
> `extract_module.py` + `extract_frontend.py` + code-read of the models, then
> code-architect synthesis. DEEP record.*

The **Data Recycle** module (`data_recycle`, category *Productivity/Data
Cleaning*, `application=True`, version 1.3) is a data-cleaning rule engine: it
finds old/stale records of any model and **archives or deletes** them through
configurable recycle rules. It is **not** auto-installed and depends only on
`mail` (for steward notifications). Its center of gravity is the
`data_recycle.model` (the rule) / `data_recycle.record` (the cleanup candidate)
pair — only two thin models and zero HTTP routes, driven by a daily cron.

## Role & Dependencies

| Depends on | Why (inferred) |
|------------|----------------|
| `mail` | `message_notify()` emails system-group stewards when manual cleanup candidates accumulate. |

**Adds on top:** per-model retention/recycle rules (domain filter + staleness
threshold), a nightly scan cron, a manual review queue, and a bespoke OWL list
view with bulk **Validate / Unselect** buttons. Dedupe/merge is **not** here — it
lives in the sibling `data_merge` module (they share the
`DataCleaningCommonListController` UI base).

## Data Model (the ERM)

| Model | What it is | Key relations |
|-------|-----------|---------------|
| `data_recycle.model` | The recycle **rule** (17 fields): target `res_model_id`→`ir.model`, `domain`, `recycle_action` (archive/unlink), `recycle_mode` (manual/automatic), staleness via `time_field_id`→`ir.model.fields` + `time_field_delta` + `time_field_delta_unit`, `include_archived`, notify config. | `res_model_id`→`ir.model`; `time_field_id`→`ir.model.fields`; `notify_user_ids`→`res.users`; `recycle_record_ids`→`data_recycle.record`. |
| `data_recycle.record` | A **cleanup candidate** (7 fields). Holds no data copy — `res_id` + `res_model_name` is a soft polymorphic pointer to the live original. | `recycle_model_id`→`data_recycle.model`; `res_model_id`→`ir.model` (related); `company_id`→`res.company` (computed). |

Security is admin-only: 2 ACLs, both `base.group_system`; no record rules.

## Behavior & Surfaces

The metadata-invisible heart is three code-read methods:

- **`_recycle_records` / `_cron_recycle_records`** — the daily cron (03:00,
  `data/ir_cron_data.xml`) sudo-searches all rules; per rule it composes a
  `Domain` of the rule `domain` **AND** `time_field <= now - relativedelta(delta)`,
  searches the target model, and diffs against existing candidates so only NEW
  `data_recycle.record` rows are created. `automatic` mode batches (5000) and
  immediately `action_validate()`s with per-batch commits; `manual` mode stages
  (50000) candidates for review.
- **`data_recycle.record.action_validate`** — the executor: groups originals into
  archive-vs-unlink buckets by `recycle_action`, calls
  `action_archive()` or `unlink()` under sudo, then unlinks the processed
  candidates. `action_discard` only sets `active=False`.
- **Notifications** — `_notify_records_to_recycle` `message_notify`s
  `notify_user_ids`, throttled by `notify_frequency` / period / `last_notification`.

**Frontend (gap #3, static):** an OWL list view `data_recycle_list`
(`DataRecycleListController` → `DataCleaningCommonListController` → `@web`
`ListController`) with a `DataRecycle.buttons` template; **Validate** ORM-calls
`action_validate` in bulk and `openRecord` opens the original target record.
**Integrations (gap #7):** none — no HTTP call sites, SDKs, or API keys.

management scope of 13.x — a governance capability other capabilities rely on.

governs DATA, not IT delivery. (Note: `apqc_odoo_map.tsv` carries no 8.0/13.0
rows, so this is an architect-justified mapping.)

## How to Drive It

```bash
# odoo shell — create a rule and stage candidates
r = env['data_recycle.model'].create({'name':'Old leads',
  'res_model_id':env.ref('crm.model_crm_lead').id,
  'time_field_delta':6,'time_field_delta_unit':'months',
  'recycle_action':'archive','recycle_mode':'manual'})
r.action_recycle_records()
# run the nightly scan + notify on demand:
env['data_recycle.model'].search([])._cron_recycle_records()
# execute staged archive/delete:
env['data_recycle.record'].search([]).action_validate()
# UI: Settings > Technical > Data Cleaning (Recycle Records) -> Validate selection
```
