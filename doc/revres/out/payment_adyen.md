# payment_adyen — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` +
> behavioral code-reads + the `PROMPT.md` template.*

The **Payment Provider: Adyen** module (`payment_adyen`, category
*Accounting/Payment Providers*, `application=False`) is the **Adyen acquirer
adapter** for Odoo's payment engine. It depends on exactly one module —
**`payment`** — and exists only to make Adyen a usable, live payment provider:
it teaches `payment.provider`/`payment.transaction`/`payment.token` how to talk
to the Adyen Checkout API over HTTP, how to drive the Adyen Web drop-in (with
3DS) in the browser, and how to ingest Adyen's HMAC-signed webhooks. It owns
**no models and no views** — four `_inherit` extensions graft Adyen credentials,
the `/payments` charge + capture/void/refund flows, and saved-card fields onto
the engine. This is a textbook **metadata gap #7**: a real external integration
whose endpoints, API-key auth, and webhook trust live in code, not field metadata.

## Role & Dependencies

| Depends on | Why |
|------------|-----|
| `payment` | The provider/transaction/token engine + the centralized outbound HTTP helper `payment.provider._send_api_request` and the guarded transaction state machine this module plugs Adyen into. |

**Adds on top:** Adyen credentials (merchant account / API key / client key / HMAC
key / API URL prefix), the direct **Adyen Web drop-in** `/payments` card flow with
client-side 3DS, **tokenization** (Adyen stored payment method + shopperReference)
and off-session recurring, **partial** manual capture / void / **partial** refunds,
and per-amount/country payment-method discovery.

**No own model, no own views** — `xml_loc≈97` is view *inheritance* (Adyen
credential fields on the provider form), QWeb inline drop-in templates, and
provider seed data (5 data files). The cross-system keys (`provider_reference`,
`provider_ref`, `adyen_shopper_reference`) bind Odoo records to Adyen objects.

## Behavior & Surfaces

- **Routes:** 5. Three public **jsonrpc** drop-in routes
  (`/payment/adyen/payment_methods`, `/payments`, `/payments/details`), one public
  HTTP **redirect-return** (`/payment/adyen/return`, csrf=False), and the public
  **POST-only webhook** (`/payment/adyen/notification`, csrf=False).
- **Views:** **0 own views** — all UX is inheritance into the provider form + the
  payment QWeb drop-in templates.
- **Frontend (static):** 1 JS file, **no OWL**, 0 registry adds — it **patches**
  `PaymentForm.prototype` to mount the Adyen Web drop-in; assets in
  `web.assets_frontend`.
- **Security:** **0 own ACL/record rules/groups** — leans on `payment`; merchant
  account, API key and HMAC key are restricted to `base.group_system`.

What metadata cannot show, established by reading the code:

- **`_send_payment_request` / `adyen_payments`** — outbound **POST `/payments`** to
  the Adyen Checkout API. `_build_request_url` builds `{prefix}.adyen.com/checkout/V{ver}/…`
  (test) / `{prefix}-checkout-live.adyenpayments.com/…` (live); `_build_request_headers`
  authenticates with **`X-API-Key: <adyen_api_key>`** + an `idempotency-key`. The
  shopper flow checks `check_access_token` (amount tamper guard) then POSTs the live
  `paymentMethod` + 3DS `browserInfo` + a `returnUrl`; the token flow POSTs
  `storedPaymentMethodId` with `ContAuth`/`Subscription`. Both `_process('adyen', …)`.
- **`AdyenController.adyen_webhook`** (`/payment/adyen/notification`) — finds the tx
  by `_search_by_reference`, then **`_verify_signature`**: recompute via
  `_compute_signature` (flatten + canonical key list, **HMAC-SHA256** with the binary
  `adyen_hmac_key`, Base64) and **constant-time compare** — mismatch/missing → HTTP
  **403 Forbidden**. On success it maps `eventCode`+`success` → a `resultCode` and
  `_process`es; the route always returns `'[accepted]'`. The HTTP `/payment/adyen/return`
  route instead re-submits `/payments/details` (3DS redirect).
- **Capture/void/refund & child txs** — `_send_{capture,void,refund}_request` POST
  `/payments/{ref}/captures|cancels|refunds` against the source `provider_reference`,
  each storing a **new distinct `pspReference`**. Adyen-initiated capture/void/refund
  webhooks spawn child transactions via `_adyen_create_child_tx`.
- **Tokenization** — on a successful authorisation with `tx.tokenize`,
  `_extract_token_values` vaults a `payment.token` only if
  `recurring.recurringDetailReference` is present (`provider_ref` = stored-PM id,
  `adyen_shopper_reference` = shopperReference); later off-session charges reuse them.

## Value-Configuration Classification

**Value model: Network (mediating-technology acquirer integration).** `payment_adyen`
interconnects two parties who would not otherwise transact directly — the
**cardholder/payer** and the **merchant** — by linking the merchant into Adyen's
card network. It shows all three mediating-technology activities: **network
promotion & contract management** (merchant-account/API-key/HMAC-key config + the
per-amount/country drop-in method discovery), **service provisioning** (creating &
confirming the `/payments` charge per transaction, with 3DS), and **infrastructure
operation** (the Adyen Checkout API server link, the drop-in client channel, the
HMAC-signed-webhook settlement loop). It is **not** transformation (chain) or
bespoke problem-solving (shop). It inherits the parent `payment` engine's
classification — the engine is the generic mediator, this module its **Adyen
realization (gap #7)**. Classified **network / support** (mirrors the
`payment_stripe` sibling; contrasts with `account_payment` = support/support, whose
own logic is ledger record-keeping).

## How to Drive It

Use the `run-odoo` skill. With a `-i payment_adyen` database and an Adyen provider
in test state:

```python
# odoo shell — provider + feature flags
p = env['payment.provider'].search([('code','=','adyen')], limit=1)
print(p.name, p.state, p.support_manual_capture, p.support_refund, p.support_tokenization)
print([m for m in dir(env['payment.transaction']) if 'adyen' in m.lower()])
tx = env['payment.transaction'].search([('provider_code','=','adyen')], limit=1)
print(tx.reference, tx.state, tx.provider_reference)  # provider_reference == Adyen pspReference
```

```bash
# webhook HMAC gate: a missing/invalid hmacSignature -> HTTP 403 Forbidden
curl -X POST https://<host>/payment/adyen/notification -H 'Content-Type: application/json' \
  -d '{"notificationItems":[{"NotificationRequestItem":{"merchantReference":"x"}}]}'
# Adyen test card: 4111 1111 1111 1111, any future expiry, any CVC
```
