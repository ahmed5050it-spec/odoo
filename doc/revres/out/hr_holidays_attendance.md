The **HR Attendance Holidays** module (`hr_holidays_attendance`, category
*Human Resources*, `application=False`, **`auto_install=True`**) is the bridge
that "convert[s] employee's extra hours to leave allocations" (its own manifest).
It activates automatically whenever both `hr_attendance` and `hr_holidays` are
installed, and declares **no business model of its own** except an analysis report
(`hr.leave.attendance.report`) — the rest is 8 `_inherit`-only extensions, ~1.5k
Python LOC. It is a pure HR **support** activity: it neither sells nor ships, it
reconciles two HR support apps so compensable overtime becomes spendable time off.

## Role & Dependencies

| Depends on | Why (inferred) |
|------------|----------------|
| `hr_attendance` | Source of the raw value: `hr.attendance.overtime.line/.rule` — the extra hours worked that this module makes "compensable as leave". |
| `hr_holidays`   | Target of the value: `hr.leave.type/.leave/.allocation/.accrual.level` — the leave/balance objects funded by overtime. |

**Adds on top:** an `overtime_deductible` leave type/allocation, a netting compute
that turns approved compensable overtime into a leave balance, a `Per Hour Worked`
accrual frequency, balance guards on requests, overtime recompute on leave change,
and an Attendance-vs-Leave analysis report.

## Data Model (the ERM — all extensions but the report)

| Model (`_inherit` / `_name`) | Adds | Role |
|------------------------------|------|------|
| **`hr.leave.type`** | `overtime_deductible` (Deduct Extra Hours) | flags a leave type funded by overtime |
| **`hr.employee`** | `_get_deductible_employee_overtime`, `get_overtime_data_by_employee` | the overtime→balance netting |
| **`hr.leave`** | `overtime_deductible`, `employee_overtime` + guards | spends overtime; blocks if over-drawn |
| **`hr.leave.allocation`** | `overtime_deductible`, `employee_overtime` + guards | overtime-funded bank; officer-edit lock |
| **`hr.leave.accrual.level`** | `frequency='worked_hours'` | accrue allocation per hour worked |
| **`hr.attendance.overtime.line/.rule`** | `compensable_as_leave` | which extra hours convert to leave |
| **`resource.calendar.leaves`** | create/write/unlink → `_update_attendances_overtime` | leave block re-triggers overtime recompute |
| **`hr.attendance`** | `(check_in,check_out,employee_id)` SQL index | speeds the overlap re-search |
| `hr.leave.attendance.report` *(own model)* | 13 fields | expected vs worked vs leave hours pivot |

Field mix is **Boolean-flag + Float-hours heavy** (6 Boolean, 6 Float): the whole
module is a handful of flags plus dynamically-netted hour totals — no stored balance.

## Behavior & Surfaces (the metadata gap)

- **Overtime → leave balance (`hr.employee._get_deductible_employee_overtime`):**
  the core conversion. `_read_group` nets **(+)** approved
  `hr.attendance.overtime.line` with `compensable_as_leave=True` **(−)** hours of
  non-allocation overtime-deductible `hr.leave` taken **(−)** hours of
  overtime-deductible `hr.leave.allocation` (confirm/validate/validate1). No stored field.
- **The deductible type (`hr.leave.type`):** with `requires_allocation=False`,
  `get_allocation_data` injects a synthetic balance = unspent overtime and
  `_compute_display_name` shows "(N hours available)"; with
  `requires_allocation=True`, `default_get` preselects it for an overtime-funded bank.
- **Guards (`_check_overtime_deductible` / `_check_employee_overtime_balance`):**
  on create/write/approve, a request or allocation that would push the net balance
  below 0 raises `ValidationError` — you can't spend more than you banked.
- **Recompute (`resource.calendar.leaves`):** create/write/unlink re-search every
  overlapping `hr.attendance` and call `_update_overtime()`, so editing a leave
  block keeps the compensable-overtime pool consistent.
- **Worked-hours accrual (`hr.leave.accrual.level`):** the `worked_hours` frequency
  makes `_get_accrual_plan_level_work_entry_prorata` pro-rate the accrued
  `number_of_days` by actual `hr.attendance` hours in the period.
- **Routes:** none. **Security:** 1 access rule, 0 record rules, 0 groups (reuses
  hr_holidays groups). **Views:** form 1, list 4, search 1, **pivot 1** (the report).
- **Frontend (static):** one backend OWL widget — `ExtraHoursSummary`, registered
  `views:extra_hours_list_view` on `web.assets_backend` — totals the employee's
  compensable / not-compensable / unspent overtime. No patches, no outbound
  HTTP/SDK integrations (gap #7 empty).

## Value-Configuration Classification

**Value model: `support` · activity_class: `support` · APQC: 7.0 Develop and Manage
Human Capital.** Per Stabell & Fjeldstad this is a support value configuration with
no value stream of its own: it administers the workforce — converting banked
overtime into leave — rather than transforming demand (chain), solving a customer
problem (shop), or mediating an exchange (network). It owns no standalone object
beyond an analysis report and exists only as `auto_install` glue between two HR
support modules, both themselves support/7.0.

## APQC PCF Hint

**7.0 Develop and Manage Human Capital** — the *manage employee time & attendance /
leave administration* sub-process: reconciling attendance overtime with time-off
allocation. It sits squarely between its parents `hr_attendance` (7.0) and
`hr_holidays` (7.0).

## How to Drive It

Use the **run-odoo** skill (`odoo shell`) — there are no routes to curl:

- `env['hr.employee'].search([], limit=5)._get_deductible_employee_overtime()`
  — net spendable overtime per employee (the conversion result).
- `env['hr.leave.type'].search([('overtime_deductible','=',True)]).mapped(('name','requires_allocation'))`
  — find the deductible leave types and their mode.
- `env['hr.attendance.overtime.line'].search([('compensable_as_leave','=',True),('status','=','approved')], limit=5).mapped(('employee_id.name','manual_duration'))`
  — the approved compensable overtime that feeds the pool.
- `env['hr.leave.attendance.report'].read_group([], ['expected_hours:sum','worked_hours:sum','leave_hours:sum'], ['employee_id'])`
  — the expected-vs-worked-vs-leave analysis.
