# base_address_extended — Reverse-Engineering Brief

> *Generated by the revres workflow: facts from `extract_module.py` /
> `extract_frontend.py` + code-read of the module, per `AGENT_WORKFLOW.md`.*

The **Extended Addresses** module (`base_address_extended`, category
*Sales/Sales*, `application=False`, `auto_install=False`) splits a partner's
free-text **street** into structured components — **street name**, **house
number** and **door/number2** — for countries that need it, and adds a curated
**city** master-data model. It owns no business document: it is a thin
extension over `res.partner` and `res.country` plus one reference model,
`res.city`. ~211 Python LOC, 162 XML LOC, 0 routes.

## Role & Dependencies

| Depends on | Why (inferred) |
|------------|----------------|
| `base` | Extends the core `res.partner` / `res.country` master data it structures. |
| `contacts` | Surfaces the structured street + city_id fields in the Contacts app forms. |

**Adds on top:** structured street fields (compute/inverse around the legacy
`street`), a `res.city` list, per-country `enforce_cities`, and inherited
form/list/search views — no new app, no document chain.

## Data Model (the ERM)

| Model (`_name`) | Description | #fields | Key relations |
|-----------------|-------------|--------:|---------------|
| **`res.city`** | City | 4 | `country_id→res.country`, `state_id→res.country.state` |
| `res.country` *(ext)* | Country | +1 | adds `enforce_cities` (Boolean) |
| `res.partner` *(ext)* | Contact | +5 | `street_name/street_number/street_number2` (Char), `city_id→res.city`, `country_enforce_cities` (related) |

**Center of gravity:** the three Char sub-fields on `res.partner`, which are
**stored compute fields with an inverse** — the canonical value stays in the
single `street`, the parts are derived. `res.city` is the only own model.

## Behavior & Surfaces

- **Split (compute):** `_compute_street_data` (`@api.depends('street')`) calls
  `tools.street_split(street)`; `ADDRESS_REGEX = ^(.*?)(\s[0-9][0-9\S]*)?(?: - (.+))?$`
  yields name / first digit-led token / the part after ` - `.
- **Join (inverse):** `_inverse_street_data` rejoins as
  `"name number"`, appending `" - number2"` — a bidirectional sync so plain
  `street` readers keep working while structured countries get the parts.
- **City fill-down:** `_onchange_city_id` copies city name/zip/state from the
  chosen `res.city`; `_onchange_country_id` clears a `city_id` whose country no
  longer matches; `city_id` is propagated via `_address_fields()`.
- **Country targeting:** `res.country.address_format` / `address_view_id` (with
  `_get_default_address_format`) decide which structured fields appear, so the
  "countries that need it" scoping is data-driven.
- **Frontend:** none — no JS/OWL/registry/patches; UX is server-side XML views
  (form 1, list 1, search 1). Security: 2 ACLs, 0 record rules, 0 groups.

## How to Drive It

Use the `run-odoo` skill. With the server up and a DB with
`-i base_address_extended`:

```python
# odoo shell
p = env['res.partner'].create({'street': 'Main Street 12 - B'})
print(p.street_name, p.street_number, p.street_number2)   # Main Street 12 B
p.write({'street_name': 'Rue Neuve', 'street_number': '5', 'street_number2': ''})
print(p.street)                                            # Rue Neuve 5
print(env['res.country'].search([('enforce_cities', '=', True)]).mapped('name'))
print(env['res.city'].search_count([]))
```
