# الربط بين العمليات الأساسية والداعمة في Odoo
# (Integrating Primary & Support Activities)

> الأنشطة الأساسية تَخلق القيمة، والداعمة تُمكّنها — لكن القيمة الحقيقية لا تظهر إلا حين
> **تترابط** الاثنتان: أن تتدفّق تكاليف الأنشطة الداعمة (رواتب، مشتريات، مصاريف) إلى
> الأنشطة الأساسية (أوامر، مشاريع، معاملات) فيُعرَف الربح الحقيقي لكل وحدة قيمة.
>
> هذه الوثيقة تشرح **آليات الربط الفعلية في Odoo**، وعمودها الفقري **المحاسبة التحليلية**.
> مكمّلة لـ `PRIMARY_ACTIVITIES_AR.md` و `SUPPORT_ACTIVITIES_AR.md` و
> `PRODUCT_VALUE_LIFECYCLE_AR.md`.

---

## 1. العمود الفقري للربط: المحاسبة التحليلية

كل التكاليف والإيرادات في Odoo تلتقي في نموذج واحد: **`account.analytic.line`** (سطر
تحليلي) مجموعةً على **`account.analytic.account`** (حساب تحليلي = «وحدة القيمة»: مشروع،
أمر، مركز تكلفة).

```
   الأنشطة الداعمة                                   الأنشطة الأساسية
  ┌──────────────┐                                 ┌──────────────┐
  │ مشتريات      │── سطر تحليلي (تكلفة) ──┐         │              │
  │ رواتب/ساعات  │── سطر تحليلي (تكلفة) ──┼──▶ account.analytic.account ◀── إيراد البيع
  │ مصاريف       │── سطر تحليلي (تكلفة) ──┘    (وحدة القيمة: مشروع/أمر)
  └──────────────┘                                 └──────────────┘
                                  │
                                  ▼
                    الربح = Σ الإيراد − Σ التكاليف الداعمة والأساسية
```

> **الفكرة المحورية:** الحساب التحليلي هو «الوعاء» الذي تصبّ فيه الأنشطة الداعمة تكاليفها
> وتصبّ فيه الأنشطة الأساسية إيراداتها — فيُحسب صافي القيمة المُنشأة.

**دليل تقني:** `hr_timesheet.hr_timesheet` يرث `account.analytic.line` — أي أن **ساعة عمل
الموظف (نشاط داعم: HRM) هي حرفياً سطر تكلفة تحليلي** يُربط بالمشروع (نشاط أساسي).

## 2. آليات الربط الست (روابط فعلية في الكود)

| # | الربط (داعم → أساسي) | الآلية في Odoo |
|---|----------------------|-----------------|
| 1 | **المشتريات → اللوجستيات/العمليات** | سعر `purchase` + التكاليف اللاحقة → تقييم المخزون (`standard_price`، طبقات التقييم) → يدخل تكلفة التصنيع |
| 2 | **HRM → العمليات/التنفيذ** | `hr_hourly_cost` (تكلفة الساعة) → تكلفة مراكز العمل في `mrp` + تكلفة المشروع في `project` |
| 3 | **HRM → التنفيذ (متجر)** | `hr_timesheet` (سطر تحليلي) → يُفوتَر عبر `sale_timesheet` (الجهد المُسلَّم) |
| 4 | **المصاريف → الخدمة** | `hr_expense` → إعادة فوترة عبر `expense_policy` على المنتج |
| 5 | **تطوير التكنولوجيا → المنتج** | `BoM` + السمات (`product`) تعرّف المنتج القابل للتصنيع/البيع |
| 6 | **البنية التحتية → الكل** | `account` + التوزيع التحليلي يلتقط كل حركة، و`approvals` بوّابات تحكّم |

## 3. الربط عبر النماذج الثلاثة

### ٣.١ في السلسلة 🏭 — الربط بتدفّق التكلفة في المخزون
```
شراء (داعم) ──▶ standard_price ──▶ تكلفة المكوّنات في BoM ──▶ تكلفة المنتج التام ──▶ COGS
HRM: hr_hourly_cost ──▶ تكلفة مركز العمل ──────────────────┘
```
الأنشطة الداعمة (شراء + عمالة) **تتجسّد في تكلفة الوحدة** المخزّنة، ثم تُقابَل بالإيراد عند
البيع → الهامش.

### ٣.٢ في المتجر 🧑‍⚕️ — الربط بالحساب التحليلي للمشروع
```
HRM: ساعات (timesheet = سطر تحليلي) ──┐
مشتريات: تراخيص/أدوات ──────────────────┼──▶ account.analytic.account (المشروع) ──▶ يُفوتَر
مصاريف: سفر (hr_expense) ───────────────┘                                          (sale_timesheet)
```
كل الأنشطة الداعمة **تُجمَّع على مشروع العميل** (الحساب التحليلي)، فيظهر ربح كل ارتباط.

### ٣.٣ في الشبكة 🔗 — الربط بحجم المعاملات/الاشتراكات
```
بنية تحتية (داعم: استضافة، منصّة) ──▶ تكلفة ثابتة موزّعة تحليلياً
                                          على عدد المعاملات/المشتركين (أساسي)
```
الأنشطة الداعمة (تشغيل المنصّة) **تُوزَّع على حجم الشبكة**؛ كلّما زادت المعاملات قلّت
التكلفة لكل معاملة (اقتصاديات الحجم).

## 4. مثال متكامل — رقمٌ يتدفّق من الداعم إلى القيمة

«مشروع تطوير برمجي» (متجر قيمة) — تتبّع الربط خطوةً بخطوة:

```
النشاط الداعم            الآلية                       السطر التحليلي على المشروع
─────────────────────────────────────────────────────────────────────────────
المشتريات   →  شراء ترخيص (purchase)        →  تكلفة:   −500
HRM         →  60 ساعة × 90 (hr_hourly_cost) →  تكلفة: −5400   (60 سطر timesheet)
المصاريف     →  سفر (hr_expense)             →  تكلفة:   −600
─────────────────────────────────────────────────────────────────────────────
الأساسي     →  فوترة 60 ساعة × 200          →  إيراد: +12000   (sale_timesheet)
═════════════════════════════════════════════════════════════════════════════
account.analytic.account (المشروع):  الربح = 12000 − 6500 = 5500
```

كل سطر داعم وكل سطر أساسي يلتقي على **نفس الحساب التحليلي**، فيُحسب صافي القيمة — هذا هو
الربط في جوهره.

## 5. الربط بالأتمتة (الأحداث التي تشغّل الربط)

الربط ليس محاسبياً فقط، بل **مُؤتمَت** عبر الأحداث (ربطاً بـ `BPMN_REVERSE_IMPLEMENTATION.md`):

| الحدث (أساسي) | يُشغّل ربطاً مع (داعم) |
|----------------|------------------------|
| تأكيد `sale.order` خدمة | إنشاء `project.task` (يستقبل ساعات HRM) |
| تأكيد `sale.order` سلعة | إنشاء `mrp.production` (يستهلك مشتريات + عمالة) |
| إتمام `mrp.production` | ترحيل تكلفة المكوّنات + مراكز العمل إلى قيمة المنتج |
| تسجيل `hr_expense` | ربطه بالحساب التحليلي للمشروع لإعادة الفوترة |
| إتمام `payment.transaction` | تفعيل الخدمة + توزيع تكلفة البنية التحتية |

> `base.automation` تربط الأنشطة الأساسية بالداعمة لحظة وقوع الحدث (Event → Function)،
> والمحاسبة التحليلية تربطها قيمةً (Cost → Account).

## 6. الخلاصة

- **الربط بين الأساسية والداعمة يتحقّق على محورين:**
  - **قيمةً (محاسبياً):** عبر **المحاسبة التحليلية** — كل تكلفة داعمة وكل إيراد أساسي
    يلتقيان على `account.analytic.account` (وحدة القيمة)، فيُحسب الربح.
  - **حدثاً (أتمتةً):** عبر `base.automation` التي تنشئ الروابط (مهمة من بيع، أمر تصنيع
    من بيع، توزيع تكلفة من معاملة).
- **روابط فعلية في الكود:** `hr_hourly_cost`→تكلفة العمليات، `hr_timesheet`(=سطر
  تحليلي)→الفوترة، `purchase`→تقييم المخزون، `hr_expense`→إعادة الفوترة، `BoM`→تعريف
  المنتج.
- **يختلف بالنموذج:** السلسلة تربط عبر **تكلفة المخزون**، المتجر عبر **الحساب التحليلي
  للمشروع**، الشبكة عبر **توزيع تكلفة البنية على حجم المعاملات**.

باختصار: العمليات الأساسية والداعمة تترابط في Odoo عبر **المحاسبة التحليلية** (الوعاء الذي
يجمع التكلفة والإيراد) و**الأتمتة** (التي تنشئ الروابط عند الأحداث) — فتتحوّل الجهود
المتفرّقة إلى **قيمة مُقاسة وربح معروف** لكل وحدة عمل.
