# تعريف المنتج وفق تهيئته (Product Configuration) في Odoo

> هذه الوثيقة تشرح كيف يُعرَّف المنتج في Odoo **عبر تهيئته** — أي بنظام **السمات
> (Attributes)** و**القيم (Values)** و**المتغيّرات (Variants)** و**المُهيّئ (Product
> Configurator)** — بحيث يصبح قالبٌ واحد قادراً على توليد عشرات المنتجات القابلة للبيع.
>
> مبنية على النماذج الفعلية في `addons/product/models/`:
> `product.attribute`, `product.attribute.value`, `product.template.attribute.line`,
> `product.template.attribute.value`, `product.template.attribute.exclusion`,
> `product.combo`. مكمّلة لـ `VALUE_AND_SERVICE_PRODUCT_MGMT.md`.

---

## 1. الفكرة الأساسية: قالب واحد → متغيّرات كثيرة

في Odoo يُفصَل **مفهوم المنتج** عن **الوحدة القابلة للبيع**:

```
            product.template  (القالب — ما يُعرّفه مدير المنتج)
                   │
       تُضاف إليه سمات (لون، مقاس ...) عبر
       product.template.attribute.line
                   │
                   ▼
            product.product  (المتغيّر — ما يُباع/يُخزَّن فعلاً)
       تيشيرت أحمر/كبير ، تيشيرت أزرق/صغير ...
```

| النموذج | الدور |
|---------|-------|
| `product.template` | **القالب**: الاسم، النوع، السعر الأساسي — المفهوم العام. |
| `product.product` | **المتغيّر**: تركيبة محدّدة من قيم السمات — الوحدة القابلة للبيع والتخزين. |

> «تهيئة المنتج» = إضافة سمات وقيم للقالب، فيتولّد منها المتغيّرات تلقائياً.

---

## 2. مكوّنات التهيئة (نماذج التهيئة)

### ٢.١ السمة `product.attribute` — البُعد (لون، مقاس، ذاكرة...)

```python
name           # اسم السمة: "اللون"، "المقاس"
create_variant # كيف تتولّد المتغيّرات (مهم جداً — انظر §3)
display_type   # كيف تُعرَض في المُهيّئ: radio / pills / select / color / multi / image
value_ids      # القيم الممكنة (أحمر، أزرق ...)
```

### ٢.٢ القيمة `product.attribute.value` — قيمة ضمن السمة

```python
name        # "أحمر"، "كبير"
html_color  # كود اللون (لِعرض color)
is_custom   # قيمة يكتبها العميل بنفسه (مثل نقش مخصّص)
```

### ٢.٣ سطر سمة القالب `product.template.attribute.line` — ربط سمة بقالب

هو الذي **يربط** سمةً بقالبٍ معيّن ويحدّد **أي القيم** متاحة لهذا المنتج:
```python
product_tmpl_id   # القالب
attribute_id      # السمة (اللون)
value_ids         # القيم المختارة لهذا المنتج (أحمر، أزرق فقط مثلاً)
```

### ٢.٤ قيمة سمة القالب `product.template.attribute.value` — القيمة على مستوى المنتج

هنا يحدث **التسعير حسب التهيئة**:
```python
price_extra   # سعر إضافي لهذه القيمة (مثلاً +20 للمقاس XXL)
exclude_for   # استثناءات (هذه القيمة تُمنع مع قيم أخرى)
ptav_active   # نشطة/معطّلة
```

> **`price_extra`** هو مفتاح «القيمة وفق التهيئة»: كل خيار يضيف قيمته السعرية الخاصة.

### ٢.٥ الاستثناءات `product.template.attribute.exclusion` — تركيبات ممنوعة

تمنع توليفات غير منطقية (مثلاً: «جلد» لا يتوفّر مع «مقاس صغير»). يتفاعل معها المُهيّئ
فيُخفي/يعطّل الخيارات غير المتوافقة.

---

## 3. الأهم: وضع توليد المتغيّرات `create_variant`

هذا الحقل يحدّد **كيف تُعرَّف المتغيّرات** — وهو جوهر التهيئة:

| القيمة | المعنى | متى تُستخدم |
|--------|--------|-----------|
| **Instantly** (`always`) | تُنشأ **كل** التوليفات الممكنة فوراً كمنتجات `product.product`. | عدد توليفات محدود ومخزّن (تيشيرت بألوان/مقاسات). |
| **Dynamically** (`dynamic`) | يُنشأ المتغيّر **فقط عند طلبه** في أمر البيع. | توليفات كثيرة جداً (تجنّب انفجار العدد). |
| **Never** (`no_variant`) | لا تُنشأ متغيّرات إطلاقاً؛ القيمة تُضاف كخيار/سعر فقط. | خيار يؤثّر على السعر دون أن يكون منتجاً منفصلاً. |

> **مثال على الانفجار:** سمة بـ 5 ألوان × 5 مقاسات × 4 أنواع قماش = **100 متغيّر**.
> `always` ينشئها كلها؛ `dynamic` ينشئ ما يُطلب فقط — لذا تُستخدم في المنتجات شديدة
> التهيئة.

ملاحظة: `display_type='multi'` (خانات متعدّدة) يتطلّب `no_variant` (قيد في الكود).

---

## 4. أنواع التهيئة الثلاثة

### ٤.١ تهيئة بالمتغيّرات (Variants) — الأكثر شيوعاً
المنتج المُهيّأ = قالب + سمات. كل توليفة = متغيّر بسعره وتكلفته ومخزونه.
**مثال:** «حذاء رياضي» بسمات: المقاس (38–44)، اللون (أبيض/أسود)، النوع (جلد/قماش).

### ٤.٢ تهيئة بالمنتجات الاختيارية (Optional / Cross-sell)
`optional_product_ids` على القالب: منتجات تُقترَح عند الشراء (بيع تكميلي).
**مثال:** عند شراء «لابتوب» يُقترَح «حقيبة» و«ضمان ممتد» و«ماوس».

### ٤.٣ تهيئة بالحزم (Combo)
`product.combo` / `product.combo.item`: العميل **يختار** من بين بدائل ضمن حزمة بسعر واحد.
**مثال:** «وجبة» = (مشروب: كولا/عصير) + (طبق: برجر/دجاج) + (إضافة: بطاطس/سلطة).

## 5. كيف يجمعها المُهيّئ (Product Configurator)

عند البيع، يقرأ المُهيّئ تهيئة القالب ويعرض الخيارات حسب `display_type`:

```
المنتج: تيشيرت
  اللون:  ● أحمر  ○ أزرق  ○ أسود        (display_type = color)
  المقاس: ○ S  ● M  ○ L  ○ XXL(+20)     (display_type = pills، price_extra)
  ⚠ "جلد + S" معطّل                      (exclusion)
        │
        ▼
  المتغيّر المختار: تيشيرت/أحمر/M
  السعر = list_price + Σ price_extra
```

سلسلة الحساب:
1. السمات والقيم المتاحة ← من `product.template.attribute.line`.
2. طريقة العرض ← `display_type`.
3. الخيارات الممنوعة ← `exclusion`.
4. السعر النهائي ← `list_price` + مجموع `price_extra` للقيم المختارة.
5. المتغيّر ← موجود (`always`) أو يُنشأ الآن (`dynamic`).

---

## 6. مثال متكامل — «حاسوب مكتبي مُهيّأ» 🖥️

```
القالب:  product.template = "حاسوب مكتبي"،  list_price = 8000

السمات (attribute_line_ids):
  • المعالج (select):   i5 (+0)   |  i7 (+2000)   |  i9 (+4500)
  • الذاكرة (radio):    8GB (+0)  |  16GB (+800)  |  32GB (+2000)
  • التخزين (pills):    SSD 512 (+0) | SSD 1TB (+700)
  • create_variant = dynamic   ← توليفات كثيرة، تُنشأ عند الطلب

الاستثناء:  i5 + 32GB  ممنوع (exclusion)

تهيئة العميل: i7 + 16GB + SSD 1TB
السعر = 8000 + 2000 + 800 + 700 = 11500
المتغيّر: يُنشأ الآن (dynamic) كـ product.product مستقلّ بسعره وتكلفته
```

---

## 7. جدول: عنصر التهيئة ↔ النموذج ↔ الدور

| العنصر | النموذج | الدور في التعريف |
|--------|---------|------------------|
| البُعد (لون/مقاس) | `product.attribute` | يعرّف نوع الخيار وطريقة عرضه وتوليد المتغيّرات |
| الخيار (أحمر) | `product.attribute.value` | قيمة ضمن السمة (+ لون/مخصّص) |
| ربط السمة بالمنتج | `product.template.attribute.line` | أي السمات/القيم متاحة لهذا القالب |
| التسعير حسب الخيار | `product.template.attribute.value` | `price_extra` لكل قيمة + الاستثناءات |
| التركيبات الممنوعة | `product.template.attribute.exclusion` | منع توليفات غير متوافقة |
| المنتج النهائي | `product.product` | المتغيّر القابل للبيع |
| الحزم/البدائل | `product.combo` / `combo_item` | تهيئة بالاختيار ضمن حزمة |
| البيع التكميلي | `optional_product_ids` | منتجات مُقترَحة |

---

## 8. الخلاصة

- **تعريف المنتج وفق التهيئة** = البدء من `product.template` ثم إضافة **سمات** و**قيم**،
  فيتولّد منها **متغيّرات** `product.product` قابلة للبيع.
- **`create_variant`** يحدّد منطق التوليد: فوري (`always`) / عند الطلب (`dynamic`) / بدون
  متغيّرات (`no_variant`) — لتفادي انفجار عدد التوليفات.
- **`price_extra`** على `product.template.attribute.value` هو ما يجعل **القيمة تتغيّر وفق
  التهيئة** (كل خيار يضيف سعره)، و**الاستثناءات** تمنع التوليفات غير المنطقية.
- ثلاثة أساليب تهيئة: **متغيّرات** (سمات)، **اختيارية** (بيع تكميلي)، **حزم Combo**
  (اختيار ضمن باقة).
- **المُهيّئ** يجمع كل ذلك وقت البيع: يعرض الخيارات (`display_type`)، يطبّق الاستثناءات،
  ويحسب السعر النهائي = `list_price` + Σ `price_extra`.

باختصار: في Odoo لا تُعرّف مئة منتج يدوياً، بل تُعرّف **قالباً واحداً وتهيئته**، فيولّد
النظام المتغيّرات وأسعارها تلقائياً.
