# العلاقة مع العمليات الداعمة (Support Activities) في Odoo

> في إطار سلسلة القيمة (Porter) ونماذج Stabell & Fjeldstad الثلاثة، تنقسم الأنشطة إلى:
> **أنشطة أساسية (Primary)** تَخلق القيمة مباشرة، و**أنشطة داعمة (Support)** تُمكّن
> الأنشطة الأساسية وتشترك فيها النماذج الثلاثة جميعاً (السلسلة، المتجر، الشبكة).
>
> هذه الوثيقة تشرح **العمليات الداعمة الأربع** وعلاقتها بالأنشطة الأساسية ونماذج القيمة،
> وتربط كلًّا منها بوحدات Odoo الفعلية. مكمّلة لـ `VALUE_MODELS_THREE_AR.md` و
> `VALUE_CONFIGURATION_METHODOLOGY.md`.

---

## 1. الفكرة: الداعمة تُمكّن الأساسية في كل النماذج

```
        ┌───────────────────────────────────────────────┐
        │   البنية التحتية للمنشأة (إدارة·مالية·محاسبة)   │  ┐
        ├───────────────────────────────────────────────┤  │
        │        إدارة الموارد البشرية (HRM)             │  │ أنشطة
        ├───────────────────────────────────────────────┤  │ داعمة
        │        تطوير التكنولوجيا (R&D / PLM)           │  │ (مشتركة)
        ├───────────────────────────────────────────────┤  │
        │            المشتريات / التوريد                 │  ┘
        ╞═══════════════════════════════════════════════╡
        │   الأنشطة الأساسية (تختلف بحسب النموذج):        │
        │   سلسلة: لوجستيات·عمليات·تسويق·خدمة            │  ← القيمة
        │   متجر:  اكتشاف·حلّ·اختيار·تنفيذ·تقييم          │  ← تُخلَق
        │   شبكة:  ترويج·تقديم خدمة·بنية تحتية            │  هنا
        └───────────────────────────────────────────────┘
```

**القاعدة:** الأنشطة الأساسية **تتغيّر** بتغيّر النموذج، أمّا الأنشطة الداعمة **فثابتة
ومشتركة** — لكن **شدّة استخدامها** تختلف بحسب النموذج (انظر §4).

## 2. العمليات الداعمة الأربع ووحدات Odoo

### ٢.١ البنية التحتية للمنشأة (Firm Infrastructure) 🏛️
الإدارة العامة، التخطيط، المالية، المحاسبة، الشؤون القانونية، الجودة.

| المهمة الداعمة | وحدة Odoo |
|----------------|-----------|
| المحاسبة والمالية | `account`, `account_payment`, `account_edi` |
| التوقيع والعقود | `sign` |
| الوثائق وإدارتها | `documents` |
| الموافقات الداخلية | `approvals` |
| لوحات القيادة والتقارير | `spreadsheet_dashboard`, محرّك التقارير |
| الشركة والإعداد | `res.company`, `base_setup` |

### ٢.٢ إدارة الموارد البشرية (HRM) 👥
التوظيف، التدريب، الرواتب، الحضور، الإجازات، الأداء.

| المهمة الداعمة | وحدة Odoo |
|----------------|-----------|
| الموظفون والهيكل | `hr`, `hr_org_chart` |
| التوظيف | `hr_recruitment` (+ `_skills`, `_survey`) |
| المهارات والكفاءات | `hr_skills` |
| الحضور والوقت | `hr_attendance`, `hr_timesheet` |
| الإجازات | `hr_holidays` |
| المصاريف | `hr_expense` |
| تكلفة ساعة العمل | `hr_hourly_cost` |

### ٢.٣ تطوير التكنولوجيا (Technology Development / R&D) 🔬
البحث والتطوير، الهندسة، إدارة دورة حياة المنتج، إدارة المعرفة.

| المهمة الداعمة | وحدة Odoo |
|----------------|-----------|
| إدارة المشاريع (R&D) | `project` |
| دورة حياة المنتج/التغييرات الهندسية (PLM/ECO) | `mrp_plm` (عند تثبيته) |
| المعرفة والتوثيق | `knowledge` (عند تثبيته) |
| تصميم المنتج (BoM، السمات) | `mrp` (BoM)، `product` (السمات/المتغيّرات) |

> **ملاحظة:** تعريف المنتج وتهيئته (`PRODUCT_CONFIGURATION_AR.md`) هو مخرَج نشاط «تطوير
> التكنولوجيا» الداعم.

### ٢.٤ المشتريات / التوريد (Procurement) 🛒
شراء المدخلات والموارد التي تستهلكها الأنشطة الأساسية.

| المهمة الداعمة | وحدة Odoo |
|----------------|-----------|
| أوامر الشراء | `purchase` |
| طلبات عروض الأسعار/المناقصات | `purchase_requisition` |
| ربط الشراء بالتصنيع/المخزون | `purchase_mrp`, `purchase_stock` |
| معلومات المورّدين | `product.supplierinfo` |

## 3. كيف تتّصل الداعمة بالأساسية (آلية الربط في Odoo)

العمليات الداعمة لا تعمل بمعزل — تتغذّى منها الأنشطة الأساسية عبر **حقول وروابط فعلية**:

| رابط الداعمة ↔ الأساسية | كيف يظهر في Odoo |
|--------------------------|-------------------|
| HRM → التصنيع/الخدمة | تكلفة ساعة العمل (`hr_hourly_cost`) تدخل في تكلفة `mrp` وفي هامش الخدمة |
| HRM → متجر القيمة | `hr_timesheet` يقيس الجهد المُسلَّم ويُفوتَر في `sale_timesheet` |
| المشتريات → السلسلة | `purchase` يغذّي تكلفة الدخول وتقييم المخزون (`standard_price`) |
| البنية التحتية → الكل | `account` يلتقط كل التكاليف/الإيرادات (محاسبة تحليلية) |
| تطوير التكنولوجيا → المنتج | `BoM` والسمات تعرّف المنتج القابل للتصنيع/البيع |
| الموافقات → كل العمليات | `approvals` بوّابات تحكّم على الشراء/الإنفاق |

> **المحاسبة التحليلية (Analytic Accounting)** هي العمود الفقري الذي يربط تكاليف الأنشطة
> الداعمة (رواتب، مشتريات، مصاريف) بالأنشطة الأساسية (أوامر، مشاريع)، فيُعرَف **الربح
> الحقيقي** لكل وحدة قيمة.

## 4. اختلاف شدّة الداعمة بحسب النموذج

رغم أن الأنشطة الداعمة مشتركة، **وزنها النسبي يختلف** بين النماذج الثلاثة:

| النشاط الداعم | السلسلة 🏭 | المتجر 🧑‍⚕️ | الشبكة 🔗 |
|---------------|-----------|-------------|-----------|
| البنية التحتية | متوسط | متوسط | **عالٍ جداً** (المنصّة = البنية) |
| الموارد البشرية | متوسط | **حرِج** (الخبراء = القيمة) | متوسط |
| تطوير التكنولوجيا | **عالٍ** (تصميم المنتج/العملية) | عالٍ (المنهجيات) | **عالٍ** (المنصّة التقنية) |
| المشتريات | **حرِج** (المواد = أكبر تكلفة) | منخفض | منخفض |

- في **السلسلة**: المشتريات وتطوير المنتج هما الأهم (المواد + التصميم).
- في **المتجر**: الموارد البشرية هي الأهم (قيمة الشركة في خبرائها وسمعتهم).
- في **الشبكة**: البنية التحتية التقنية هي الأهم (المنصّة نفسها هي الخدمة).

---

## 5. مثال متكامل — تتبّع التكلفة من الداعمة إلى القيمة

«مشروع استشاري» (متجر قيمة) — كيف تتجمّع الأنشطة الداعمة في القيمة النهائية:

```
المشتريات:        ترخيص برمجي للمشروع           →  500
الموارد البشرية:   40 ساعة استشاري × 90 (hr_hourly_cost) → 3600
المصاريف:         سفر (hr_expense)               →  400
─────────────────────────────────────────────────────────
التكلفة عبر الأنشطة الداعمة (محاسبة تحليلية)      = 4500
الإيراد (sale_timesheet: 40 ساعة × 200)          = 8000
الهامش المحقّق                                    = 3500
```

كل الأنشطة الداعمة (شراء + رواتب + مصاريف) تُجمَّع عبر **المحاسبة التحليلية** على المشروع،
فيظهر الربح الحقيقي للنشاط الأساسي (حلّ مشكلة العميل).

---

## 6. الخلاصة

- **الأنشطة الداعمة أربع**: البنية التحتية، الموارد البشرية، تطوير التكنولوجيا،
  المشتريات — وتشترك فيها نماذج القيمة الثلاثة جميعاً.
- **في Odoo** تتحقّق عبر وحدات: `account/sign/documents/approvals` (بنية تحتية)،
  `hr*` (موارد بشرية)، `project/mrp_plm/knowledge` (تطوير)، `purchase*` (مشتريات).
- **العلاقة بالأساسية** تتحقّق عبر روابط فعلية (تكلفة الساعة، تقييم المخزون، الـ timesheet)
  و**المحاسبة التحليلية** التي تجمع تكاليف الداعمة على الأنشطة الأساسية.
- **شدّة الداعمة تختلف بالنموذج:** المشتريات/التطوير للسلسلة، الموارد البشرية للمتجر،
  البنية التحتية التقنية للشبكة.

باختصار: العمليات الداعمة هي **البنية التحتية التي تُمكّن خلق القيمة** في النماذج الثلاثة،
وOdoO يربطها بالأنشطة الأساسية عبر التكلفة والمحاسبة التحليلية ليُعرَف الربح الحقيقي لكل
وحدة قيمة.
