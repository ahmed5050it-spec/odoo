# قيمة المنتج عبر مراحل دورة الحياة في Odoo
# (How Product Value Is Determined Across the Lifecycle)

> هذه الوثيقة تشرح **كيف تُعرَف قيمة المنتج (التكلفة والسعر والهامش)** وهو ينتقل عبر مراحل
> دورة حياته في Odoo — من التعريف، إلى الشراء/التصنيع، إلى التخزين، إلى البيع والفوترة وما
> بعد البيع — مع **أمثلة على منتجات حقيقية**.
>
> مبنية على: `addons/stock_account/models/product.py` (طرق التقييم)،
> `addons/sale_margin` (الهامش)، و `product.template`. مكمّلة لوثيقتَي
> `VALUE_AND_SERVICE_PRODUCT_MGMT.md` و `VALUE_CONFIGURATION_METHODOLOGY.md`.

---

## 1. الفكرة الأساسية: قيمتان تتطوّران عبر المراحل

كل منتج في Odoo يحمل **قيمتين** تُعرَّفان وتُحدَّثان في مراحل مختلفة:

| القيمة | الحقل | متى تُعرَف |
|--------|-------|-----------|
| **التكلفة** (Cost) | `standard_price` | تتكوّن عند الشراء/التصنيع وتُحدَّث في المخزون |
| **السعر** (Sales Price) | `list_price` | يُحدَّد عند التعريف ويُعدّل بالـ Pricelist عند البيع |
| **الهامش** (Margin) | `margin` (محسوب) | يتحقّق فعلياً عند البيع/الفوترة |

**الهامش = السعر − التكلفة** — وهو القيمة المُحتجَزة (captured value). الفكرة أن **التكلفة
تُبنى تدريجياً عبر المراحل**، بينما **السعر يُعرَض ويُتحقّق** في مرحلة البيع.

---

## 2. مراحل دورة الحياة وكيف تُعرَف القيمة في كل مرحلة

```
①التعريف → ②الشراء → ③التصنيع → ④التخزين → ⑤البيع → ⑥التسليم/الفوترة → ⑦ما بعد البيع
 list_price   سعر      تكلفة      تقييم      Pricelist    COGS +        إعادة فوترة
 standard_price الشراء  BoM+العمالة المخزون   + الهامش     الإيراد        التكاليف
```

### ① مرحلة التعريف (Design / Definition)
يُنشئ مدير المنتج سجل `product.template` ويحدّد:
- **`list_price`** = السعر المبدئي المستهدف (القيمة المعروضة للعميل).
- **`standard_price`** = تكلفة تقديرية مبدئية (تُستخدم قبل معرفة التكلفة الحقيقية).
- **`type`**: سلعة / خدمة / combo، و **`categ_id`** التي تحدّد **طريقة التقييم**.

> القيمة هنا **مخطَّطة/تقديرية** — لم تتحقّق بعد.

### ② مرحلة الشراء (Purchase)
عند استلام بضاعة مشتراة:
- سعر أمر الشراء + **التكاليف اللاحقة (Landed Costs)** كالشحن والجمارك → تُسجَّل كقيمة
  دخول المخزون.
- إذا كانت طريقة التكلفة `fifo` أو `average` → يُحدَّث `standard_price` تلقائياً من سعر
  الشراء الفعلي.

> القيمة هنا **تتحقّق فعلياً** أول مرة (التكلفة الحقيقية للدخول).

### ③ مرحلة التصنيع (Manufacturing)
للمنتجات المصنّعة، تُحسب تكلفة المنتج التام من:
- **تكلفة المكوّنات** من قائمة المواد (BoM)، **+**
- **تكلفة مراكز العمل** (ساعات العمل/الآلة × التكلفة بالساعة).

تكلفة أمر التصنيع كلها تُضاف كقيمة للمنتج التام عند إنهاء الأمر.

> القيمة هنا = **مجموع تكاليف المدخلات** (منطق "سلسلة القيمة / Value Chain").

### ④ مرحلة التخزين (Inventory Valuation) — قلب الموضوع
طريقة التقييم على `product.category` (`property_cost_method`) تحدّد **كيف تُعرَف قيمة كل
وحدة في المخزون**:

| الطريقة | كيف تُحسب القيمة | مثال |
|---------|------------------|------|
| **Standard** (سعر معياري) | تكلفة ثابتة محدّدة يدوياً؛ الفروق تذهب لحساب فروقات. | منتجات ذات تكلفة مستقرة. |
| **FIFO** (الوارد أولاً يصرف أولاً) | كل وحدة تُقيَّم بتكلفة دفعتها الفعلية بالترتيب. | منتجات تتغيّر أسعارها وتحتاج دقّة. |
| **AVCO** (متوسط التكلفة) | متوسط مرجّح يُعاد حسابه مع كل استلام. | سلع متجانسة تُشترى بكميات. |

كل حركة مخزون تُنشئ **طبقة تقييم (stock valuation layer)** تسجّل الكمية، تكلفة الوحدة،
والقيمة — فيصبح لديك سجل دقيق لقيمة المخزون لحظةً بلحظة.

ومع **التقييم الدائم (Perpetual / real_time)** تُرحَّل القيمة محاسبياً تلقائياً إلى حسابات
المخزون.

> القيمة هنا **محفوظة ومُتتبَّعة طبقةً بطبقة**.

### ⑤ مرحلة البيع (Sale)
- يُؤخذ **`list_price`** كأساس، ثم تُطبّق **قوائم الأسعار (Pricelist)**: خصم كمية، شريحة
  عميل، فترة عرض، عملة.
- يَظهر **الهامش** على سطر أمر البيع: `margin = السعر − purchase_price` (التكلفة) من
  `sale_margin`.

> القيمة هنا = **القيمة المعروضة فعلياً للعميل** + **الهامش المتوقَّع**.

### ⑥ مرحلة التسليم/الفوترة (Delivery / Invoicing)
- عند التسليم: تُخرَج الكمية من المخزون بقيمتها (COGS — تكلفة البضاعة المباعة) حسب طريقة
  التقييم.
- **`invoice_policy`**: «المطلوب» (تُفوتر عند الطلب) أو «المُسلَّم» (تُفوتر عند التسليم/
  الإنجاز).
- عند الفوترة يتحقّق **الإيراد**، ويُحسب **الهامش الفعلي = الإيراد − COGS**.

> القيمة هنا **تتحقّق نهائياً** (إيراد مقابل تكلفة فعلية = ربح محقّق).

### ⑦ مرحلة ما بعد البيع (After-sales / Service)
- إعادة فوترة المصاريف (`expense_policy`)، الصيانة/الإصلاح، الاشتراكات المتجدّدة.
- للخدمات: القيمة تُتتبَّع بالساعات (timesheet) أو المراحل (milestones).

> القيمة هنا **تستمر** (قيمة متكرّرة أو خدمية ما بعد البيع).

## 3. أمثلة على منتجات (كيف تختلف القيمة بحسب نوع المنتج)

### مثال ١ — كرسي مكتب مُصنَّع 🪑 (Goods / سلسلة قيمة)
```
التعريف:   list_price = 500 ج،  standard_price تقديري = 300 ج،  type=consu
الشراء:    خشب + قماش + مسامير  → تكلفة مكوّنات 220 ج (FIFO)
التصنيع:   BoM (220) + عمالة مركز العمل (60) = تكلفة تامة 280 ج
التخزين:   طبقة تقييم: 1 كرسي × 280 ج
البيع:     Pricelist لتاجر جملة → 450 ج  (هامش متوقّع 170 ج)
الفوترة:   COGS = 280 ج،  الإيراد = 450 ج،  الهامش المحقّق = 170 ج
```
**القيمة تُبنى تراكمياً** (مكوّنات → عمالة → تكلفة تامة) ثم تتحقّق كهامش عند البيع.

### مثال ٢ — جهاز لابتوب يُشترى ويُباع 💻 (تجارة / Resale)
```
التعريف:   list_price = 4000 ج،  type=consu،  طريقة AVCO
الشراء:    دفعة 10 أجهزة بـ 3000 ثم دفعة 10 بـ 3200 → متوسط 3100 ج
التخزين:   كل وحدة تُقيَّم بـ 3100 ج (AVCO)
البيع:     سعر التجزئة 4000 ج  → هامش 900 ج للوحدة
```
**القيمة هنا تعتمد على متوسط تكلفة الشراء** (لا تصنيع) — يتغيّر الهامش مع تغيّر أسعار المورّد.

### مثال ٣ — خدمة استشارة بالساعة 🧑‍💼 (Service / Value Shop)
```
التعريف:   type=service،  service_type=timesheet،  invoice_policy=delivered
           list_price = 200 ج/ساعة،  standard_price (تكلفة الموظف) = 90 ج/ساعة
البيع:     أمر بيع 40 ساعة  → عند التأكيد يُنشأ project + task
التنفيذ:   تُسجَّل الساعات على timesheet (تتبّع القيمة المُسلَّمة)
الفوترة:   تُفوتر الساعات المُنجَزة فعلاً  →  هامش = (200−90) × الساعات
```
**القيمة تُعرَف بالجهد المُسلَّم** (ساعات)، وتتحقّق عند تسليم العمل — منطق «متجر القيمة».

### مثال ٤ — اشتراك برمجي شهري ☁️ (Service / Value Network)
```
التعريف:   type=service،  invoice_policy=order (مدفوع مقدّماً)
           list_price = 100 ج/شهر
البيع:     اشتراك متجدّد → فاتورة شهرية تلقائية
القيمة:    إيراد متكرّر (MRR)؛ القيمة تنمو بعدد المشتركين (حجم الشبكة)
```
**القيمة متكرّرة وتُعرَف دورياً** — تنمو مع حجم الشبكة لا مع وحدة واحدة.

### مثال ٥ — منتج بمتغيّرات (تيشيرت بألوان/مقاسات) 👕 (Variants)
```
القالب:    product.template = "تيشيرت"،  list_price = 150 ج
المتغيّرات: أحمر/كبير، أزرق/صغير ... (product.product)
القيمة:    سعر إضافي للمتغيّر (مثلاً +20 ج للمقاس XXL)،  وتكلفة لكل متغيّر
```
**القيمة تُعرَّف على القالب وتُعدَّل لكل متغيّر** عبر السعر الإضافي للسمة.

## 4. جدول: المرحلة ↔ حقل القيمة ↔ النموذج

| المرحلة | ما الذي يُعرِّف القيمة | الحقل/النموذج في Odoo |
|---------|----------------------|----------------------|
| التعريف | السعر والتكلفة المبدئيان | `list_price`, `standard_price` |
| الشراء | تكلفة الدخول + التكاليف اللاحقة | أمر الشراء، Landed Costs، `property_cost_method` |
| التصنيع | تكلفة المكوّنات + العمالة | BoM، مراكز العمل، `mrp` |
| التخزين | طريقة التقييم + الطبقات | `property_cost_method` (standard/fifo/average)، stock valuation layer |
| البيع | السعر السياقي + الهامش المتوقّع | `product.pricelist`، `sale_margin.margin` |
| الفوترة | COGS مقابل الإيراد | `invoice_policy`، التقييم الدائم، الهامش المحقّق |
| ما بعد البيع | إعادة فوترة وخدمات متكرّرة | `expense_policy`، timesheet، الاشتراكات |

## 5. الربط بمنهجية تكوين القيمة (Value Configuration)

كما في `VALUE_CONFIGURATION_METHODOLOGY.md`، **طريقة تعريف القيمة عبر المراحل تعكس منطق
المنشأة**:

| المنطق | كيف تُعرَف القيمة عبر المراحل | مثال |
|--------|-------------------------------|------|
| **سلسلة القيمة** (تحويل) | تراكم التكلفة: مكوّنات → تصنيع → COGS → هامش | الكرسي المصنّع 🪑 |
| **متجر القيمة** (حلّ مشكلة) | بالجهد المُسلَّم (ساعات/مراحل)، قيمة = السمعة | الاستشارة 🧑‍💼 |
| **شبكة القيمة** (وساطة) | إيراد متكرّر ينمو بحجم الشبكة | الاشتراك ☁️ |

## 6. الخلاصة

- **قيمة المنتج ليست رقماً ثابتاً، بل تتطوّر عبر المراحل:** التكلفة **تُبنى تراكمياً**
  (شراء → تصنيع → تخزين)، والسعر **يُعرَض ويُتحقّق** (بيع → فوترة)، والهامش = الفرق.
- **طريقة التقييم** (`standard` / `fifo` / `average`) على فئة المنتج هي التي تحدّد **كيف
  تُعرَف قيمة كل وحدة في المخزون**، وكل حركة تُسجَّل في **طبقة تقييم**.
- **القيمة تتحقّق فعلياً عند الفوترة**: الإيراد مقابل COGS = الهامش المحقّق.
- **نوع المنتج يغيّر منطق القيمة:** سلعة مصنّعة (تراكم تكلفة)، خدمة (جهد مُسلَّم)، اشتراك
  (إيراد متكرّر) — كما توضّح الأمثلة الخمسة.

باختصار: في Odoo «تعرف القيمة» بمتابعة **التكلفة وهي تتراكم** عبر مراحل الشراء/التصنيع/
التخزين، ثم **السعر والهامش وهما يتحقّقان** عند البيع والفوترة — وكل ذلك مُسجَّل في حقول
`standard_price` و `list_price` و `margin` وطبقات تقييم المخزون.
