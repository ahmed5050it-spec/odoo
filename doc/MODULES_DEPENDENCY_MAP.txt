═══════════════════════════════════════════════════════════════════════════════
KEY OBSERVATIONS
═══════════════════════════════════════════════════════════════════════════════

1. **Accounting is the core:** account module has 151 direct dependents.
   This reflects Odoo's ERP nature — financials = mandatory business layer.

2. **Web framework is essential:** web module (31 dependents) is auto-installed.
   Almost all interactive features depend on it.

3. **Feature modules form hubs:** sale, hr, purchase, mrp, stock each collect
   5-20 specialized modules (sales_team, sale_management, sale_account, etc.).
   This is a clean architecture: core + feature + specialization.

4. **Test modules are deep:** test_event_full chains 13 module dependencies.
   Complex workflows (event booking + sales + website + payment) are well-tested.

5. **Localization adds depth:** l10n_* modules depend on account, adding
   4-6 levels per country (e.g., l10n_be_intrastat depends on stock, account, …).
   A production DB might have 5-10 country packs.

6. **Safe loading order:** Dependency graph ensures no module loads before its
   dependencies. Phases in update mode ensure new modules don't interfere with
   upgrades of existing modules.
